# Current rules

This file is a digest of the rules in force in the decision log, entries D1–D164 and B1–B36. Agents read it instead of the log and open an entry only for its reasoning or history (D161). The log wins wherever the two differ. Update this file in the same commit as each new entry.

## How the build works
- Build Core first; Undercurrent foundations use synthetic data and frozen consumed contracts, and pass their field gates before affecting agents. (D14, D19, D20)
- Steps name goal, deliverables, dependencies, stop point, unblocks, exit criterion and status. Blocked agents stop without stubs or fake producers. (D19, D41)
- Use separate worktrees/branches and fast-forward main only to the exact reviewed, hosted-passing SHA. Fixes and rebases need fresh approval and hosted results; no routine local full check is added. (D41, D46, D116, D153)
- Use fresh coders per slice and fresh reviewers; designers draft designs, drafters record decisions, readers map sources and runners execute commands. (D116 item 1, D152, D160)
- Build two to four slices; failed preregistered bounds permit two additional slices, each after one labelled diagnostic and fresh ruling. A third addition or changed bounds, traffic or eligibility needs the owner. (D152 item 2, D160 item 1)
- Ruled designs proceed without owner approval unless reserved decisions are reached. Keep the owner summary first; list reserved items and ask them together immediately after the ruling. (D117, D160 item 3)
- Small, single-package nonsensitive tickets get PM briefs ruled at first review; medium tickets get designers without readers; providers, credentials, money, sandbox or freezes require full reader-assisted design and fresh ruling. (D152 item 5)
- Review each slice once for standards and specification together; review close documents with unreviewed code once. Stand-ins may close tickets; Fable audits after reset and findings open fix tickets. (D152 item 3, D160 items 2, 5)
- Block only for violated acceptance/ruling/contract, secrets, authority/disclosure/sandbox bypass, wrong money, data loss/corruption/recovery, or missing/ineffective tests for these. Other findings are notes; re-review blocking fixes only for the finding. (D152 item 3)
- Coders run focused tests, one plain verbose run per changed package, gofmt and host vet/staticcheck; changed build constraints add five-target vet/staticcheck. Measure only what ticket/ruling requests. (D152 item 1)
- Changed locking, goroutines, channels or shared state require local package race and affected-row twentyfold race runs; hosted full checks include race on all three systems. (D152 item 1, D153)
- Rule breaks cover permissions/disclosure, credentials, recovery, sandbox and money: named tests fail, exact restoration passes. Fuzz new or changed-code targets for 120 seconds; all seeds run in checks. (D116 item 6, D152 item 1)
- CI runs on build/**, docs/** and fix/** pushes and manual dispatch, cancelling superseded runs per ref. Main pushes start no run; Check result requires successful classification and full-matrix success or valid document exemption. (D153 item 1)
- Markdown-only/empty diffs may skip the matrix, but need PM link/LF checks. Revisit the exemption if tracked Markdown becomes code/tool/test input. Manual dispatch runs the full matrix. (D128, D153)
- The check runs pinned-toolchain verification, gofmt, vet, staticcheck, online govulncheck, import boundaries, cgo-free tests, race and cross-builds; static analysis/builds cover all five supported targets. CI supplies three native systems. (D42, D133, D137, D153)
- Tests/race use count=1 and thirty-minute package limits; race above twenty-five minutes is recorded in slice evidence and escalated to the owner. (D127, D131)
- Routine guarded branch/passing-main pushes need no owner question or ticket-close wait. Scan every outgoing commit's patch, message, identity and paths; private records push separately. (D145, D146, D153 items 4–5)
- Public push scans reject merges, credentials, private/personal material, wrong identity and unsigned-off workflow changes; machine terms require contextual reading. Credentials, identity and privacy have no override; records scans still reject credentials/merges. (D145, D153 item 5)
- Protect main against deletion/force pushes; require linear history and Actions Check result without bypass, strict up-to-date mode or creation exemption. These controls do not defeat malicious authorized writers. (D146, D153)
- Use pinned GitHub-created actions, read-only workflow permissions and external-fork approval; no workflow PR trigger/secrets or Actions-created/approved PRs. Retain secret push protection and Dependabot alerts without its PRs. (D133, D153)
- Close documents land once: public ticket/status/register changes in project; brief, ruling, evidence and owner answers in private records. A ticket adds no build record; its Answer and evidence say what it built. Required decision/freeze records accompany their slice. (D116 item 3, D125, D145, D161)
- State step status only on ROADMAPS' board and its own roadmap Status line, updated together; contract versions/status only in CONTRACTS' table. Other documents point there. (D116 item 4)
- Keep one plain-sentence notes file per ticket, receipts only when cited, and raw evidence references by path/SHA-256. A ticket's exceptions, rulings and answers stay in its notes, ruling and evidence. (D116, D160 item 4, D161)
- Write an entry only when a standing rule, scope or owner gate changes: short, with originator and what it amends, no quotes, evidence paragraphs, line citations or pointers into earlier entries; change this file in the same commit (D161). Build decisions may revise marked proposals/inferences, not owner reservations. Use package-scoped Conventional Commits and LF text. (D31, B1, D161)
- Keep decisions, evidence and agent instructions/roles in private records, absent from public history. Only decisions/evidence may quote the owner, and new entries do not; public text/messages omit personal paths, machine/settings/program descriptions and use the published identity. (D135, D136, D145)
- The PM removes redundancy and decides reversible matters outside reservations; record changed repository rules as assistant decisions and report procedure changes. Start frontier tickets without routine approval. (D121, D152 item 4, D160 item 3)
- At one provider's 0.95 usage window move build roles to the other and report it; both at 0.95 means stop at the next slice boundary. Ask optional owner questions once and continue independent work. (D152 item 4)
- One PM session runs up to three tickets; write its handoff once per session. A watcher wakes the PM after fifteen inactive minutes with pending work. Designers get LSP; coders test unless measurement holds the machine. Report each ticket's timing briefly, without per-ticket pace analysis; in-depth analysis comes in the owner's periodic audits. (D160 items 4, 6, 9, 10, D162)
- Numerically bounded tickets start with one profiled acceptance-driver run. After a smallest-history smoke, each instance uses a quiet-machine runner writing its own admission record. (D160 items 7–8)
- Evaluate architecture against declared workload, accepted throughput, backlog/latency, contention/rework and whole-process/model costs; distinguish assumptions, calculations and measurements. Busy refusals are not delivery. Preserve social scope and safety; calibration is not capacity. (D78, D79, B15)

## Owner-reserved decisions
- Reserve D52 approvals, breaking contracts, toolchains, dependencies, owner-decision/workflow changes, art sign-offs and actions needing personal keys, money, accounts or machine to the owner. Workflow guard overrides are not authorization. (D29, D41, D52, D125, D152 item 4, D153)
- The owner sets capability/budget ceilings; authorized Orchestrators issue narrower context/task grants. Expanded action, target, budget, duration or delegation returns to the owner; valid in-scope work needs no repeated consent. (D82, B7)
- Only the colony owner authorizes exact policy activation, now or at one not-before time. Core executes it; edits, hierarchy and Undercurrent confer no activation authority. (D65, D66)
- Only the colony owner approves imported local/global workspace exclusions and revisions; updates affect future captures, never admitted submissions. (D75, D112)
- Dependencies need function, licence, transitive modules, size, maintenance, Go floor and removal records; x modules need entries. Test/tool/copy/vendor dependencies retain obligations; isolate copied code with source/licence. Use libraries for security/OS/edge-heavy formats; never invent cryptography. (D29)
- Every default-art generator change needs both map and character contact-sheet approval. Allowed modules do not replace explicit pixel maps with rule-generated shapes. (D103, D104, D105)

## Core and the ledger

- Log actions, turns, approvals, money, messages, workspace/check events and router measurements. Private content stays in agent directories, ledger-hashed; large bodies use body storage and router call decisions a separate JSON-lines record. (D33)

- Allow configurable concurrent contexts, never simultaneous live turns in one context. Core version-checks shared files and atomically records assignments/reservations; short typed transitions publish durable effects before projections. Expensive work runs outside. (D22, B7, D88 item 1)
- Keep model tools small/stable/versioned with permission-aware discovery. Normalize only declared unambiguous argument equivalents. One continuation owner governs turns; owner-agreed immutable-input compaction preserves later progress, has no tool loop and uses existing budgets. (D88 items 2–5)
- Use private worktree scratch per context/workspace; Core alone advances canonical main by guarded fast-forward. Humans use promotion too; canonical main is never checked out. (D16, D17, D18, D48, D77)
- A second same-agent context writing busy task scratch uses a temporary worktree from its last commit. Core commits observations, merges cleanly when safe, reports conflicts/notices and records author provenance. Other agents contribute through canonical. (D22, D23)
- Host capture includes tracked changes/deletions and nonignored new files, never trusts the mutable index. Captured repository ignores apply immediately; pinned normalization/exclusions govern capture, with raw hashes distinct from Git identity. (D60, D74, D75, D76)
- Admit before capture: four immutable checkpoints per declared context/workspace FIFO. Capacity/exclusive-capture contention returns busy immediately without snapshot, capture queue, writer interruption or automatic retry. (D62, D70, B4)
- Distinguish local-parent ancestry from foreign train predecessors: failed local parents terminate dependent suffixes; removed foreign predecessors rebuild survivors and rerun the full gate without reintroducing withdrawn changes. (B4, D77)
- Validate bounded cumulative candidates concurrently; publish only the ordered successful prefix. Original submissions stay immutable; separately bind derived generations, predecessors, evidence, requirements and attribution. (D56, D58, D77, B5)
- Requests outlive turns/views. Same ID/submission retrieves original state; mismatches error and different IDs stay separate. Results remain in the original context, passively available without completion-only model turns. (D53, D58, D63)
- Only submitting context/owner cancels promotion via a separate command; turn cancellation/view closure does not. Finalize passing evidence → durable intent → guarded durable Git update → durable acceptance → release; intent closes cancellation. (D57, D59, D77)
- Recover proven effects without execution retry: old tip means interruption, target means complete acceptance bookkeeping once. Fence prior writers and block unproven effects. No-change needs a proven accepted predecessor and performs no checks, ref update or acceptance. (D55, D59, D71, D77)

## Contracts
- Contracts comprise standard-library Go packages, versioned golden samples and owning/dependent register entries. Drafts change freely; consumers build against frozen capabilities, never unspecified placeholder payloads. (D40, B2)
- The PM freezes completed code, evidence and exact record after joint advisor approval; this supplies integration sign-off without owner packets. Freeze producer-ready catalogue parts before producer code; record ownership, callers, consumers, privacy and replay essentials. (D40, B2, D113, D125)
- Frozen contracts evolve additively; breaking changes need owner decisions listing affected steps. Preserve historical bytes/goldens and decoding compatibility; unsupported consumed versions stop clearly. (D35, D40, D125, D163, D164)
- Preserve F0/F2 group, pin, admission, scratch, witness, finalization and activation rules; exact definitions are in package documentation, versions/status in the register. (D111, D115, D118, D119, D123, D124)
- Law-format v1 objects are closed; add versions read beside old ones, preserving old values/digests without semantic upgrading. Host parser limits may tighten, never widen. (B12, D114)
- Shared-state consumers need all contributing families: both private revisions; task changes plus review results; work plus paid children/endings/unit charges. Preserve canonical submission schemas and cross-record rules; producer-fingerprint changes need visible decisions. (D139, D140, D144, D148, D154)
- Reader checkpoints are process-only hints: freshly verify prefix/predecessor, issue only after completed numeric reads and successful close, fall back on invalid proof, retain real I/O/close errors and never weaken ordinary verification. (D157)
