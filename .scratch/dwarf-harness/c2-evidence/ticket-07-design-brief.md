# Ticket 07 design brief — second-writer temporary scratch

## 0. Owner summary

Ticket 07 builds the workspace mechanism for a second turn of the **same agent** to edit a task safely: its first write is routed to a new temporary worktree cut from the task's last Core-recorded commit, never to the occupied task directory.
Core observes and commits each completed writer's eligible changes, records who authored them and which scratch they came from, and merges a finished temporary scratch back when the task is free.
An unchanged task fast-forwards; a moved task uses Git's explicit three-way base. Conflicts stay private work, preserve both histories, and produce a durable notice for the task's next naturally scheduled turn.
Capture and merge-back cannot interleave. Capture still returns busy immediately; a merge-back may wait, within its caller's context, and does not hold the task through validation.
These are C2 service operations and package-test drills, not an agent scheduler. C3 later supplies authenticated bindings, starts/ends turns, delivers notices and authorizes body reads.
No operation here accepts a promotion, changes `main`, supplies a validator, activates policy or claims hostile-process isolation. Harness use remains testing-only.
**Owner gate OG-F7:** freeze the proposed F2-07 addition after its contract slice is built, evidenced and ruled, before its producer is implemented. The same answer signs off that frozen-contract slice reaching `main` (D40/D41). Record-free mechanics may land first. D117 requires no owner design-approval question; no new dependency or D52 change is proposed.
**Consequences:** a temporary can coexist with its author's dedicated scratch; its parent is explicit. Private merge does not make task edits canonically represented/disposable. Partial filesystem writes retain original/intended histories, block normal access and require explicit safe retry; unexpected third-value interference needs owner repair, never overwrite. Full path sets that exceed the ledger's line/group limits are explicitly refused, not truncated. These conditional scratch rules and retained-input/report costs are included in the freeze packet.
Sources: `.scratch/dwarf-harness/issues/07-merge-a-second-writer-through-temporary-scratch.md:12,28-30`; `docs/DECISIONS.md:71-76,504-505,1645-1650,1906-1910,1920-1921`; `docs/ROADMAP-CORE.md:279-289,303,336,437`; `docs/DESIGN-CORE-AND-LAUNCHERS.md:248,251`; `contract/ledger/doc.go:330-350`.

### 2.1 Boundary and API (P1–P3)

D23 private editing is not the ticket 06 promotion train. The new public surface operates only private branches/worktrees; `mergeTrees`, capture tokens and submission seals remain unexported, and `RequestPromotion` still ends unconditionally in `no_validator`. Package tests exercise the private surface and invoke ticket 06's unexported admission/integration only to prove immutable-checkpoint interactions. No validator seam is added. Sources: `docs/DECISIONS.md:340-342`; `docs/ROADMAP-CORE.md:279,283,289`; `internal/core/workspace/doc.go:1-6,293-307`; ticket 06 ruling `.scratch/dwarf-harness/c2-evidence/ticket-06-design-ruling.md:13`.

Replace the old identity-free exported `BeginWrite(ctx, scratchID)` with the following typed private-work routing surface. Migrate every package caller/test; do not leave a public identity-free bypass or compatibility alias. Its physical shared-lease primitive becomes unexported and retains the existing reservation behavior.

```go
type WriteBinding struct {
    WriterID, ContextID, AgentID, TaskAgentID, TaskScratchID uuid.UUID
}
type Writer struct { /* service-minted, opaque ownership token */ }
func (s *Service) BeginWrite(ctx context.Context, b WriteBinding) (*Writer, error)
func (w *Writer) Scratch() Scratch
func (w *Writer) BeginWrite(ctx context.Context) (release func(), err error)
func (w *Writer) CommitObserved(ctx context.Context) (Observation, error)
func (w *Writer) Close() // idempotent release of logical occupancy, no Git/ledger effect
func (s *Service) MergeBack(ctx context.Context, temporaryID uuid.UUID) (MergeBackResult, error)
func (s *Service) RetryMergeBack(ctx context.Context, mergeBackID uuid.UUID) (MergeBackResult, error)
func (s *Service) RepairScratchTip(ctx context.Context, scratchID uuid.UUID) error
func (s *Service) ScratchNotices(ctx context.Context, taskContextID, taskScratchID uuid.UUID, after uint64) ([]ScratchNotice, error)
```

`BeginWrite` denotes the turn's **first actual write access**, not turn start. It creates/routes the writer and acquires no capture. `Writer.BeginWrite` protects each actual tool edit with an idempotent physical shared lease; the first tool also uses that method before touching files. A logical writer owns routing until `Close`, even between tools; a promotion capture may run between physical edits. `CommitObserved` is called at the end of that writer's turn, after its tools have released, before `Close`. These two lifetimes are distinct; never keep a physical write lease for a whole turn or validation. `Writer.Scratch` returns only the routed directory and immutable identity. `Observation` exposes its ID, committed tree/commit and record sequence; `MergeBackResult` exposes its ID, outcome, target commit/tree when applied, notice sequence and conflict digest when present. `ScratchNotice` is specified in §2.6. Sources: `docs/DECISIONS.md:71-75,504`; `docs/ROADMAP-CORE.md:283,437`; `internal/core/workspace/scratch.go:157-199`; `internal/core/workspace/doc.go:216-239`; P1–P3 settle this interface, which the sources do not prescribe.

C3 authenticates the binding, including both agent IDs and the task's owner; C2 validates UUIDv7 shape, equality of agent IDs, scratch/task-context relationships and lease ownership. This is the existing trusted-host pattern, **not** a new authenticator or context→agent authority database. C2 does not claim that matching caller-supplied IDs authenticates a caller. All writer methods reject forged/wrong-service/closed handles with `ErrInvalid`/`ErrClosed` and check service poisoning. Same `WriterID` + exact binding returns the existing live handle; changed binding gives `ErrWriterMismatch`; another live writer ID for the same author context gives immediate `context_busy`. A closed handle cannot be revived; C3 owns durable turn IDs/receipts/restart, not this in-memory writer-routing index. ### 2.2 Routing, occupation and creation (P2–P4)

The task's own context gets its dedicated task scratch if it has no other logical writer. A different context of the same agent always gets a temporary scratch; it never receives the task directory even when the task is briefly between tools or idle. Other agents are refused with `ErrNotBound`, rather than given a temporary scratch. Two turns in one context remain forbidden. The logical writer (first write to turn end), plus physical leases/exclusive holders for actual mutation, defines occupation; a capture alone does not turn a same-context request into a second turn. Sources: `docs/DECISIONS.md:62,71,75`; `docs/DESIGN-CORE-AND-LAUNCHERS.md:215,467`; `docs/ROADMAP-CORE.md:301-302,389`; P2 resolves the idle-foreign-context case conservatively.

Under the per-task routing lock, snapshot the parent's last acknowledged **observation/merge-back commit**, initially its recorded `base_commit`, not mutable HEAD/index/files or `main`. Hold a short read/routing guard against concurrent private-tip publication while choosing that base. A dirty occupied parent is not captured: the second writer starts with the parent's latest **committed** bytes and excludes the first writer's in-progress edits. Verify the private branch equals that known tip; a different ref gives `scratch_tip_mismatch`, no overwrite. Create a fresh eight-hex directory/branch, with the existing three-ID collision limit, pinned materialization and pre-check for case/prefix collisions, using an explicit commit argument in `createWorktree`. Dedicated creation continues to choose `main`; temporary creation chooses the saved parent tip. The anchor retains the fork commit. Objects/ref/worktree precede the creation record; definite append failure cleans a never-exposed scratch, uncertain append retains it and poisons as today. Sources: ticket 07 `:28`; `docs/DECISIONS.md:71`; `internal/core/workspace/scratch.go:82-155`; `worktree.go:95-196`; `doc.go:123-142,380-386`.

A temporary scratch belongs to its authoring context, has `parent_scratch_id` identifying the task, and is not entered in the dedicated `pairs` map. It may coexist with that author's dedicated scratch. Do not reuse a conflicted scratch for a new turn: each conflicting first-write access gets its own recorded scratch; repeated calls for one live writer return the same one. Temporary parents must be open dedicated scratches in the same workspace; nesting is refused. A parent with open temporary children cannot close (`ErrTemporaryChildren`), repeated under exclusion; thus no merge-back target vanishes. These conditional F2-07 rules apply only to records carrying a parent, leaving every old dedicated log valid. Sources: `contract/ledger/doc.go:307-333`; `docs/DECISIONS.md:76`; `docs/ROADMAP-CORE.md:284,303`; ticket 05 ruling `:37`; P3/P4.

### 2.3 Observing and committing private work (P5–P7)

`CommitObserved` freezes this logical writer against further `Writer.BeginWrite`, waits only within `ctx` for its outstanding tool leases, then takes the same pool's exclusion and `MaxBytes` allowance (a new observation reservation kind, no K-slot). Captures still acquire immediately-or-busy. No unrelated Git history or colony-wide mutex is held while waiting. If capacity/availability/capture fails, return the existing typed refusal, thaw the writer and keep its work/branch untouched; the caller may explicitly retry. No automatic capture retry. `Close` releases the writer without pretending an unsuccessful observation was committed. Service `Close` waits for logical writers, tool leases and calls; an already-owned writer can finish/release while service shutdown waits. Sources: `docs/DECISIONS.md:72,1741-1744,1832`; `internal/core/workspace/reserve.go:61-147,201-229`; `doc.go:423-427`; P5.

Observe through the **existing host full-tree engine**, with baseline = acknowledged private-tip tree and an additional host-built trusted tracked-path set = union of anchor and tip **path/mode listings**. Tip modes win for equal paths. Do not create a Git “union tree”: anchor `a` and tip `a/x` cannot coexist in one tree. The non-following walk classifies actual files; trusted names absent or replaced by directory/file-prefix are deletions, and regular recreated names remain eligible despite ignores. Extend only private-observation capture inputs for these additional trusted names; admission baseline/delta rules are untouched. Initial private index loads the tip, removes absent entries and adds observed eligible regular files as today. No mutable index supplies eligibility. Use pinned current inputs; unexpected branch tip refuses. Canonical observed tree becomes commit tree; raw identity remains distinct, no submission/admission. Sources: `docs/DECISIONS.md:72`; `docs/ROADMAP-CORE.md:283-284`; `internal/core/workspace/doc.go:146-212`; `.scratch/dwarf-harness/spec.md:397`; P6.

Create a deterministic single-parent Core commit even for an unchanged tree: parent = previous private tip; dates = observation UUIDv7 seconds; identity = existing Core identity; message exactly `dwarf-harness scratch observation\n\nscratch <scratch ID>\nobservation <observation ID>`. Factor the mechanical commit helper from `integrationCommit`, leaving generation message/identity and `integration-rules/1` unchanged. Retain this commit by CAS under `refs/dwarf-harness/scratch-commits/<observation ID>` before its record. Publish the manifest and pin it in the observation commit; append `workspace.scratch_changed` before updating the private branch by old-tip CAS. The record is authority, the branch is its repairable Git projection. A post-ack CAS failure reports `scratch_tip_mismatch` and blocks new writes/merge/capture on that scratch; it never loses the acknowledged commit. Open may recreate a missing retention ref, but never overwrite an unexpected branch. Sources: `internal/core/workspace/integrate.go:75-115`; `doc.go:137-142,255-268,357-369`; `docs/DECISIONS.md:71-72`; P7.

The observation records (a) author context, (b) scratch and optional task parent, (c) previous/new commit and tree, (d) full current `changed_paths` relative to its immutable anchor, (e) this observation's `written_paths` relative to its prior tip, and (f) manifest/input bindings. Compute both path sets with NUL-delimited Git tree comparison, including deletions and both names of renames (no rename inference); path-byte sort and de-duplicate. Reject invalid UTF-8 and ledger-size overflow before recording, never truncate. Keep the event history rather than replacing a path's previous author with its newest author. Sources: ticket 07 `:29`; `docs/DECISIONS.md:76`; `docs/ROADMAP-CORE.md:288`; `docs/DESIGN-UNDERCURRENT.md:613`; P8/P9.

### 2.4 Merge-back base, exclusion and landing (P10–P12)

`MergeBack` accepts only an open, observed temporary scratch with no logical writer/tool lease or live request. Acquire its source closure-style exclusion (immediate busy if occupied), observe its trusted anchor/tip paths and require exact source-tip tree; keep source exclusion until merge/disposal ends. Wait within ctx for parent logical writer and physical/capture/closure/admission holders to release. Atomically take a **sole mutation writer** on parent in the same pool: block new writers and make capture/closure/admission immediately `scratch_busy`, no K-slot. This is writer-side waiting, not capture queueing. Today's shared `beginWrite` alone is insufficient. Recheck both scratches under their guards. Sources: `docs/DECISIONS.md:73,504`; `docs/DESIGN-CORE-AND-LAUNCHERS.md:215`; `internal/core/workspace/reserve.go:16-21,72-75,201-229`; advisor notes `local://t07-map.md:535-544`; P10.

Before any task-file mutation, observe the task against its trusted eligibility union and require its observed tree equals its acknowledged tip tree; otherwise `ErrUncommittedEdits`, with both scratches intact. Reserve the observation byte allowance before this check, release bytes after observation, keep only the mutation guard through publication/landing. The parent may have pending checkpoints; their captured trees/generations do not change and are not ended. The operation holds no train lock and changes no train predecessor, `main` or represented anchor. Sources: `docs/DECISIONS.md:73,380,504`; `internal/core/workspace/doc.go:293-309,435-446`; P11.

Let F be the temporary scratch's immutable **fork commit/tree**, P the task's current acknowledged commit/tree, and S the temporary source commit/tree. If P's commit is exactly F, result = S and mode = `fast_forward`; do not synthesize a commit. Otherwise call existing `mergeTrees(F.tree, P.tree, S.tree)`. Never infer a base through `merge-base`, use `main`, or use an admitted checkpoint's delta base. A clean result gets one deterministic Core commit with P as its only parent, date from merge-back UUIDv7 and message `dwarf-harness scratch merge-back\n\nscratch <temporary ID>\nmerge-back <merge-back ID>`; source/fork provenance lives explicitly in the event, not in Git's author identity. Existing pinned integration environment, Git 2.45 floor, no tree attributes/drivers, status-based conflicts and derived-case check apply unchanged. Sources: ticket 07 `:29`; `docs/DECISIONS.md:73`; `internal/core/workspace/integrate.go:39-115`; `doc.go:244-268`; P12.

**One materialization recipe (P13).** Existing pinned capture/materialization environment, fresh private index: `read-tree --end-of-options <actual-tree>`; `update-index --refresh`; `read-tree -m -u --end-of-options <actual-tree> <target-tree>`. Actual-tree is P initially and verified intermediate O on retry. Never seed from child index, use reset, or trust status/stderr for tree equality. Before writing, check every target addition and prefix/file-directory replacement, including **ignored** entries: an obstruction not represented in actual-tree is preserved/refused (`ErrUnrepresentedEdits`), because Git overwrites ignored collisions. After checkout, re-observe trusted **P/target path-list union**; failed deletions remain tracked evidence even when ignored. Require exact target tree/absence **before branch CAS**. After a crash, explicit retry may clean/reacquire the exact own marker matching its prepared record; Open does not remove admin locks blindly. No filesystem-transaction/power-loss claim. ### 2.5 Provenance, admission and represented state (P8, P14)

Each merge-back names its source observation and records all source `written_paths` relative to the fork tree with the **source author's** context and parent scratch. Task-local observations remain separate events, so merged work is not re-labelled as authored by the task merely because it lands there. Preserve observation/merge edges and from/to trees in the ledger; this is provenance history, not a last-writer-wins author map or a new line-blame/credit allocation policy. An agent's later edit to the same path creates another observation, leaving earlier contributors traceable. Sources: `docs/DECISIONS.md:76`; `docs/DESIGN-UNDERCURRENT.md:59,613-614,617`; P8.

Relevance means intersection of a merge-back's source-written paths with the captured **local delta** paths (delta-base→sealed tree), not predecessor→aggregate paths. Replay validates the IDs, workspace/scratch ancestry and order from operational records without reading bodies. Absent keys preserve all F2-06 samples and mean the historical single-context provenance. The requesting context remains `context_id`; extra authors come from the named immutable events. ### 2.6 Conflicts, notices and C3 delivery (P16)

A merge conflict or derived case collision moves no task branch/index/file, publishes/pins the existing deterministic `conflictReport`, records an outcome, and keeps both scratches and commits open. No automatic resolution, conflict-tree checkout or public promotion occurs. A subsequent explicit call may re-merge the retained source after task work advances; it produces a new attempt, never rewrites an old result. Sources: `docs/DECISIONS.md:73-74`; `docs/DESIGN-UNDERCURRENT.md:614`; `internal/core/workspace/integrate.go:16-21,57-71,119-160`; ticket 06 ruling `:24`; P16.

`ScratchNotices` returns durable merge-back result records for **this task context and scratch** after the supplied record sequence, ordered by sequence. Each notice includes merge-back/temporary/parent IDs, author context, outcome, source-written paths, full current parent changed paths when applied, and a conflict digest when applicable. Cursor 0 reads all; empty means none; invalid or foreign binding gives `ErrNotBound`; historical closed-task notices remain readable through the trusted-host service binding. No “delivered” bit, automatic follow-up turn, destructive dequeue or acknowledgement record is added. This is C3's replayable notice input; C3 surfaces it in the next naturally scheduled task turn and authorizes body reads. Package tests query this API, close/reopen the real store/service and read the identical notice. Sources: ticket 07 `:30`; `docs/DECISIONS.md:74`; `docs/ROADMAP-CORE.md:283,336,437`; ticket 06 brief `:768`; P16.

### 2.7 Durability, failures and cancellation (P17–P18)

For clean merge, objects + `refs/dwarf-harness/scratch-commits/<merge-back ID>` precede **prepared** `workspace.scratch_merge_back` binding F/P/S/target, inputs, source paths and task pre-write raw manifest. Its pin retains manifest **plus that inputs document and every referenced host-file body**; owner input updates cannot collect retry prerequisites. Preserve per-revision `capture_inputs_pinned.body_refs` for exact-set checks without old-body reads during replay. Acknowledgement precedes mutation. After checkout, full-tree deletion verification, index installation/verification, owned-lock cleanup and branch CAS, append **applied** (`fast_forward` or `merged`) with full parent changed paths/notice and prepared-pin unpin. Only acknowledged applied advances parent private tip/disposes source. Conflict is direct terminal report-pinned result, no preparation/target. Sources: `contract/ledger/doc.go:291-302`; `internal/core/workspace/doc.go:137-142,255-276,311-319`; `docs/DESIGN-CORE-AND-LAUNCHERS.md:248`; P17.

A file/index/branch failure or cancellation after prepared is recorded as `write_failed` when the store is usable (no error text/host path in the payload), leaves the attempt unresolved and retains P, S, target, manifest and scratch directories. The task is `merge_back_pending`: ordinary writers, admission and closure refuse rather than capturing or editing a half-installed result. The task still receives the failure notice as work. Before prepared, cancellation returns `ctx.Err()` and records nothing; no scratch is discarded. `RetryMergeBack` is an **explicit host call**, never Open's automatic effect replay; it reuses the prepared plan and does not re-merge against new state.

On explicit retry rematerialize **retained prepared inputs**, reacquire source/destination guards and observe trusted P/target/source names. Require branch ∈ {P,target}; eligible paths outside source delta match P; each affected path/mode/blob is P, target or its legitimate prepared addition/deletion absence. Ignore/untracked obstructions are never discarded. Third value gives `merge_back_interference`, all bytes/proofs intact. Build O from actual disk with existing capture engine; seed/refresh new index from O and apply exactly O→target (§2.4). Verify target files/deletions/index before CAS; CAS only from P, accept target ref only with verified files/index. Already-complete target gets missing applied bookkeeping with **no effect replay**. Open reports/reconstructs pending block/pins/refs, runs no merge/capture/checkout and writes no record; explicit retry by ID required. Sources: `local://t07-git-retry-probe.md:1553-1561`; `docs/DESIGN-CORE-AND-LAUNCHERS.md:248,253`; `internal/core/workspace/doc.go:351-369,400-421,423-427`; P18.

Acknowledged source-observation branch repair is narrower: update a still-recorded old tip to the recorded new tip by CAS only, or accept an already-equal tip; unexpected values stay pending. No source file checkout is involved. An uncertain append follows existing poisoning and store-recovery rules; never guess whether prepared/applied/closure exists in memory. Keep all failure reports pinned until the affected scratch's closure; closure emits unpins in their original pin order, including F2-06's report pins. No `gc`, `prune` or repack is introduced. ## 3. Records and durability

**F2-07 is required.** D23 needs parent/provenance, changed paths and a distinct merge-back event; none exists in frozen F2-05/F2-06. | Operation | Durable group, in this order | Actor/context |
|---|---|---|
| temporary creation | `workspace.scratch_created` with parent | core / author context |
| writer observation | `workspace.scratch_changed`, immediate manifest `ledger.body_pin`, then prior observation-manifest unpin when present | core / scratch author |

| clean applied | `workspace.scratch_merge_back(fast_forward|merged)`, prepared-manifest unpin | core / task context |

No commit position is fixed except **immediate pins and following ordered unpins**, leaving space for C3's command receipt. No second store, authority file, command schema or notice-delivery record.
