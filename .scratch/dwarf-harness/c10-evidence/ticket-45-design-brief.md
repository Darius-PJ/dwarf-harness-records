#### P1 — two genuine readings; recommendation: retain the start gate

**Reading A: literal pre-start wait — recommended.** `ROADMAP-CORE.md:930` says C10 waits for “C3's Core-owned child/execution interface” and “implementation can begin only with owner-frozen relevant C1/B11 contracts”; its §3 row repeats C2/C3 (`:979`). B28 item 9, dated 2026-10-17, ends “C10 for C3” (`docs/DECISIONS.md:2248`). Ticket 45 itself retains the interface-freeze bullet (`:22`). On this reading, **45 is blocked until the scope of that gate is repaired and its retained required interfaces are actually specified/frozen**. It is not enough to wait for ticket 16's shutdown tests: no producer ticket, schema or registered home exists for the supposed C3 interface (`local://t45-gate-supplement.md:27-32,95-104`).

**Reading B: independent executor now; C3 integration/qualification later — considered and not selected without a recorded clarification.** This is supported by the ticket's exact after-C2/no-C3-integration wording (`.scratch/dwarf-harness/issues/45-run-and-positively-close-a-restricted-windows-process-tree.md:7-8,24`), `C2 --> C10` and the board's C2-only prerequisite (`docs/ROADMAPS.md:83,180`), and Core's “separate core track after C2” with “no dependencies beyond” that graph (`docs/DESIGN-CORE-AND-LAUNCHERS.md:704`). It is **not** a proposal to fake C3: real immutable test input, a real native output/closure boundary and real hostile descendants could constitute the standalone executor; C3 and the C4 consumer would integrate later. This is the strongest coherent decomposition reading, not the strawman “after C2 waives all freezes” (`local://t45-gate-supplement.md:74-97,112-118`).

**Why choose A now?** B can resolve the *integration* wording, but does not by itself satisfy or remove ticket 45's own mandatory **pre-build interface freeze**. No source states which relevant B11 interface has been frozen, which actual producer owns its specification, or why review of a private Core API would count as a D40/D125 contract freeze. Treating RC:930/B28 as later integration **and** treating that unfulfilled freeze condition as an ordinary in-layer review would make two unrecorded changes. Correctness is better served by an explicit reconciliation than by converting missing ownership into permission. The blocked conclusion is therefore a deliberate P1 interpretation, **not a factual claim that C3 already has a known contract it will eventually freeze** (`docs/CONTRACTS.md:3,7-19,25-47`; `docs/DECISIONS.md:206-214,2124-2125`; `.scratch/dwarf-harness/issues/45-run-and-positively-close-a-restricted-windows-process-tree.md:16-24`; `local://t45-gate-supplement.md:95-104`).

**What closes the conflict, without an indefinite ghost dependency?** The PM must record which start reading controls and make the retained freeze gate executable: name the real interface producer/scope/home, or explicitly clarify that the standalone native API is an in-layer implementation whose runtime proof is distinct from formal catalogue freezes. Under the current six-contract boundary the possible D125 home for actual durable C10 facts is an additive `ledger-format` family, not a seventh executor contract; the sources currently assign neither its owner nor its family. A technical reconciliation needs a recorded `«B-NEXT»`/amendment at the applicable gate, not a design-approval question. If it changes a reserved owner decision rather than reconciles assistant-level descriptions, ask the owner before that amendment under D41; otherwise the advisor/PM process handles it. Do not silently add 15/16 as schema-producing blockers, and do not ask the owner now to freeze a nonexistent specification (`docs/CONTRACTS.md:7-19,25,34,38-47`; `docs/ROADMAP-CORE.md:220`; `docs/DECISIONS.md:214,1545,1917-1927,1934-1938,2124-2125`; `docs/ROADMAPS.md:230-232`; `local://t45-gate-supplement.md:99-104,128-130`).

**Defender qualification (P3).** The `git.exe` process exclusions are an observed, owner-selected build-test configuration, not a missing D52 approval or a switch-off of Defender, and not a `scratch/` or `runs/` folder exclusion. B28 explicitly selects none for the product; its Limits preserve product capacity under Defender with no exclusion. Therefore the ticket's enabled-Defender machine gate is met, but later measurements must disclose the exclusions and cannot be passed off as the product's no-exclusion capacity baseline or compared unqualified with pre-exclusion figures. No exclusion removal or machine change is requested by this design (`docs/DECISIONS.md:2213,2236,2257`; `docs/DESIGN-CORE-AND-LAUNCHERS.md:225,888,1595`; `.scratch/dwarf-harness/issues/45-run-and-positively-close-a-restricted-windows-process-tree.md:23,32`).

## §3. Core-internal interface and supported run profile

### 3.1. Request, result and error types

**Small synchronous interface (P6/P9/P11).** Expose exactly the following module-level shapes; enum constants and error details follow the tables below. No public OS-handle injection, live-output subscriber, generic capability callback or replaceable native backend. A caller invokes `Run` in its own goroutine if it needs asynchronous scheduling and cancels that call's context; the same interface is used in the real tests. The module owns the native handles, not a caller that may disappear. This is Core-internal code, not a registered contract (`local://t45-ruling.md:55,77-80`; `docs/ROADMAP-CORE.md:433,950,959`; `docs/DECISIONS.md:276`).

```go
func Open(ctx context.Context, root string) (*Executor, error)
func (e *Executor) Run(ctx context.Context, request Request) (Receipt, error)
func (e *Executor) Close() error

type InputFile struct {
    Path string
    Data []byte
}
type Limits struct {
    Wall          time.Duration
    UserCPU       time.Duration
    CPUPercent    uint32
    JobCommitBytes uint64
    Processes     uint32
    InputBytes    uint64
    OutputBytes   uint64
    StopGrace     time.Duration
}
type Request struct {
    Program  string
    Args     []string
    Files    []InputFile
    Stdin    []byte
    Limits   Limits
    Deadline time.Time
}
type Usage struct {
    User100ns, Kernel100ns             uint64
    PeakJobMemoryBytes, PeakProcessMemoryBytes uint64
    ReadBytes, WriteBytes, OtherBytes uint64
    TotalProcesses                    uint32
}
type Receipt struct {
    RootID, RunID             uuid.UUID
    ProfileSID                string
    State                     RunState
    Outcome                   Outcome
    ExitCode                  uint32
    ExitCodeKnown             bool
    RootExited, TreeExited    bool
    ResourcesReusable         bool
    OutputState               OutputState
    Stdout, Stderr             []byte
    InputBytes                uint64
    CreatedUTC, ResumedUTC, ClosedUTC time.Time
    Setup, Execution, Stop    time.Duration
    Usage                     Usage
    UsageKnown                bool
}
```

`Program` is the relative path of exactly one staged `.exe` in `Files`; it is never a host path, shell string or implicit `COMSPEC` invocation. `Args` excludes argv[0]; the module prepends the staged executable's absolute path and uses the Windows argument quoting routine, with a non-null explicit application name. `Files` and `Stdin` are already-authorized immutable bytes from the trusted Core-side caller; the caller must not mutate their backing arrays until `Run` returns. Validate lengths/checked sums before copying, then take owned copies; returned output slices are owned by the receipt and never mutated by a later run. This avoids reading mutable host input trees, symlink traversal, shared hard links or ambient scratch/Git access. Later grants/body reads/subject preparation remain with their real producers (`local://t45-ruling.md:55,64,77`; `.scratch/dwarf-harness/issues/45-run-and-positively-close-a-restricted-windows-process-tree.md:28-30`; `docs/DESIGN-CORE-AND-LAUNCHERS.md:985-987`).

**No incidental/unlimited defaults.** All limit fields are mandatory and positive. `CPUPercent` is 1–100, mapped to the native hard-cap rate in hundredths of a percent. `UserCPU` is a finite Job aggregate **user-mode** CPU-time limit in 100-ns units; `CPUPercent` additionally limits CPU rate, including the native scheduler's rate accounting. `JobCommitBytes` is the native aggregate committed-memory limit, not a promise that all kernel/shared/physical memory is quota-accounted. `Processes` includes the root. Define the exact `InputBytes` charge by checked unsigned addition: `len(Stdin) + len(Program)+1 + sum(len(Args[i])+1) + sum(len(Files[i].Path)+1+len(Files[i].Data))`, with string lengths in UTF-8 bytes; the `+1` values charge separators/terminators, and the executable data counts. The fixed host-derived environment/path prefix is not caller input. `OutputBytes` is one shared retention budget for stdout+stderr; zero is not “unlimited.” Require `UserCPU` to be a positive exact multiple of 100 ns, `OutputBytes <= MaxInt`, and all native conversions to fit their signed/unsigned ABI fields. The profile's precise native guarantees are §4's limit table; never label user CPU as total CPU or committed memory as RAM (`docs/DECISIONS.md:737`; `.scratch/dwarf-harness/issues/45-run-and-positively-close-a-restricted-windows-process-tree.md:32`; `local://t45-ruling.md:68,81`; P9).

`Deadline` must be present. If already expired at admission, return `NotAdmitted`/`TimedOut` with `context.DeadlineExceeded` and no fence/native effects; a pre-canceled context likewise returns its real cause without admission. Otherwise take one host time sample, convert the requested deadline to a remaining duration, and use a monotonic timer for `min(Limits.Wall, requested remaining time, parent-context remaining time)`. Setup counts against that wall budget. Check cancellation/expiry before profile creation, before process creation and immediately before resume; expiry during a native call prevents a subsequent resume. No wall-clock regression can extend a run after admission. `StopGrace` separately bounds the stop-proof/I/O-drain/cleanup protocol after stopping or natural tree exit; the canceled caller context is **not** reused as its deadline. Checks occur between local native calls; this is not a claim to preempt a hung trusted Windows kernel/API (`local://t45-ruling.md:67,77,80-81`; `docs/ROADMAP-CORE.md:949`; `.scratch/dwarf-harness/issues/45-run-and-positively-close-a-restricted-windows-process-tree.md:31-32`; P9/P11).

**Admission/lifecycle.** `Open` requires a non-nil context, an absolute dedicated local root and the private-marker conditions in §5. It acquires the OS lock and admits no unresolved fence. One root is one physical slot: overlapping calls return `ErrBusy` immediately, with no native creation, fence or hidden queue. `Close` atomically forbids new admissions, requests stop of the active call, waits for that call's bounded stop protocol and releases the OS root lock last; repeat `Close` returns its stored result. It closes native handles once safe; the exceptional lifetime of an unconfirmed pending native I/O allocation is §4.4, not a reason to free kernel-referenced memory early. Once quarantined, this executor never silently clears its fence or admits another run, even if a later close observes a dead tree. A zero/unopened/closed executor refuses calls, never panics or starts a process (`docs/ROADMAP-CORE.md:950,956,959`; `local://t45-ruling.md:55,67,77-80`; P11).

| Type/state | Exact meaning |
|---|---|
| `RunState` | `NotAdmitted` (zero/no RunID), `Closed` (positive no-process/job-empty proof), `Quarantined` (unconfirmed native or local resources) |
| `Outcome` | `NotStarted` (zero), `Exited`, `Canceled`, `TimedOut`, `OutputExceeded`, `Shutdown`, `NativeFailure`; quarantine is independently represented by `State` |
| `OutputState` | `Unpublishable` (zero) or `CompleteSealed`. Both are host-private; `CompleteSealed` is **not** C4 acceptance or permission to disclose |
| Nil error | Only ordinary root exit code 0, tree positively closed, complete bounded output, native accounting known and cleanup/reuse confirmed. Nothing “passes validation” |
| Nonzero root exit | `Outcome:Exited`, native `ExitCode` only with `ExitCodeKnown:true`, `ErrProcessExit`; no guessing from an exit-code token that a tree stopped. Failure to query it is native failure with `ExitCodeKnown:false`, never an invented zero |
| Context/limit/native error | Preserve the actual cause (`context.Canceled`/`DeadlineExceeded`, `ErrOutputLimit` or native/file error) and still run stop/cleanup; return the populated receipt for Core's private diagnostics |
| Quarantine | `State:Quarantined`, `TreeExited` only if actually proved, `ResourcesReusable:false`, `OutputState:Unpublishable`, error wrapping `ErrQuarantined`; the original cause is retained with `errors.Join` |
| Cleanup pending after positive exit | `State:Closed`, positive flags retained, `ResourcesReusable:false`, output unpublishable, `ErrCleanupPending`; a valid `closed` fence permits later cleanup, or a completely removed run requires parent-directory flush on explicit reopen. The marker-removal orphan case in §5 is quarantine, not a falsely recoverable closed fence |

Declare `ErrInvalid`, `ErrInvalidRoot`, `ErrUnsupported`, `ErrBusy`, `ErrClosed`, `ErrQuarantined`, `ErrCleanupPending`, `ErrOutputLimit`, `ErrProcessExit`. A `*NativeError` carries bounded stage name, Win32/HRESULT code and wrapped error; it does not hide errors by replacing them with exit code 0. `NotAdmitted` returns no fake process/profile/timestamps. Tests assert behavior/state and `errors.Is`/native classes, not English wording. `CreatedUTC` comes from the root's native creation time; `ResumedUTC`/`ClosedUTC` are host observations, not claims about the exact first/last machine instruction. Durations are monotonic; `Usage` retains exact native units/knownness. All fields are Core-private (`docs/DECISIONS.md:214,737`; `docs/DESIGN-CORE-AND-LAUNCHERS.md:985-987`; `local://t45-ruling.md:55,67-68,77`).

Duration boundaries (P11): admission `A`; actual successful resume `R`; stop entry `S` (first accepted stop cause, or positive natural tree exit); final return-ready cleanup/quarantine `F`. `Setup=A→R` when resumed, otherwise `A→S`; `Execution=R→S` or zero if never resumed; `Stop=S→F`. Stop includes kill/proof/drain/cleanup, not merely the termination syscall. `ClosedUTC` is the host observation of proved native tree exit (including no-created proof), zero if unknown; it is not an fsync time. Not-admitted process timestamps/durations remain zero. The external evidence also measures whole Open/Run/Close cost, so setup and supervisor overhead are not hidden (`local://t45-ruling.md:67,77,83-84`; P11/P12).

Use `uint8` enums with the table's listed order starting at zero. The public error carrier is `type NativeError struct { Stage string; Code uint32; HRESULT bool; Err error }`, with `Error`/`Unwrap`; stage strings are fixed internal operation names, never untrusted command text. Store the actual native code and distinguish HRESULT from Win32; do not read stale `GetLastError` after HRESULT-returning/successful APIs, or fabricate a native error code for a locally detected policy mismatch. Other validation/filesystem errors retain their real wrapped cause (`local://t45-ruling.md:55,57,65,77,81`; P6/P11).

An idle healthy `Close` returns nil after releasing resources. Closing an active healthy run returns nil if its shutdown proof/cleanup/resource closes succeed; the active `Run` receives `Shutdown`/`ErrClosed`, not success. `Close` does not propagate an ordinary former nonzero exit as a close failure, but reports retained quarantine/cleanup-pending or real resource-close errors. After cleanup-pending, another `Run` returns `ErrCleanupPending`; explicit `Close`/`Open` is the recovery path for a valid closed fence, not a hidden retry in `Run`. A nil/unopened executor returns `ErrClosed` rather than panicking; non-Windows methods consistently return `ErrUnsupported`. A nil context/zero deadline is `ErrInvalid`, with no admission. All of these are Core-internal lifecycle/error semantics, not a frozen cross-layer format (`local://t45-ruling.md:55,67,77-80`; P6/P11).

### 3.2. Run roots, authorized input and output ownership

**Roots and exchange (P8/P9).** The only per-run filesystem grants are the newly created `input/`, private `work/` and the fresh AppContainer's own required private profile state, plus the supported OS runtime baseline. No live Git/worktree, shared cache, caller home, colony directory, credentials or arbitrary host path is granted. Input is copied bytes, not a mount/junction/hard link or a shared reader into a producer's storage. The child receives no Core-channel handle. All speculative stdout/stderr/work state stays host-private; this module exposes only its bounded final stdio receipt and never copies files out or publishes them (`.scratch/dwarf-harness/issues/45-run-and-positively-close-a-restricted-windows-process-tree.md:28-31`; `docs/DESIGN-CORE-AND-LAUNCHERS.md:985-987`; `docs/ROADMAP-CORE.md:955`; `local://t45-ruling.md:55,64-68,77-78`).

**P8 choice: a fresh writable private work/tmp root, bounded stdio exchange, no file-output export.** “OutputBytes” limits data returned across the executor→Core channel, not all scratch writes a process attempts. A program may use its own fresh scratch; it cannot make that scratch an agent-visible artifact transport. This implements a usable process executor without claiming a nonexistent per-directory NTFS disk quota. There is no promised hard private-disk/physical-RAM quota and no file-output collection path in this profile; later C4 qualification must not silently assume either. Actual scratch/profile disk use is measured, not advertised as capped. The finite wall/CPU/commit/process/input/stdout+stderr limits of §4 remain mandatory and fail closed. Alternatives and the rationale are P8 in §9; this is a proposed implementation choice for the advisor, not an expansion of B11 or a changed qualification gate (`docs/DECISIONS.md:736-738`; `.scratch/dwarf-harness/issues/45-run-and-positively-close-a-restricted-windows-process-tree.md:28,32`; `local://t45-ruling.md:64,68,81-84`).

Validate every relative file name/`Program` using `fs.ValidPath` (also refuse `"."`), Windows `filepath.Localize`/`IsLocal`, valid UTF-8/no NUL, no backslash/colon, and no segment ending in a dot or space. Refuse duplicate/aliased creates through native create-new semantics; do not guess Unicode case folding or normalize two distinct author inputs into one file. `Program` must exactly name one input. Construct directories/files only in the fresh Core-only run tree, with no child yet and no external source traversal; refuse any unexpected existing/reparse entry. Seal input ACLs read/execute only before the launch. Root/run/fence parents remain host-only except the minimum traversal needed to their explicitly granted children. Work files/profile state are never returned as output, and post-stop cleanup never follows their links (`docs/DESIGN-CORE-AND-LAUNCHERS.md:985-987`; `.scratch/dwarf-harness/issues/45-run-and-positively-close-a-restricted-windows-process-tree.md:28-30`; `local://t45-ruling.md:77-79`).

Build a fresh double-NUL Unicode environment, never `os.Environ()`: only system-API-derived `SystemRoot`/`WINDIR` and initially `TEMP`/`TMP=work/`; no inherited credentials, HOME/USERPROFILE, PATH, Git/Go flags or launcher handles. The Microsoft launch page documents native temp rerouting under the fresh profile, but whether it overrides an explicit environment block is unverified. Therefore the supported private-temp scope is **this run's work or owned profile**, not a promise that one exact environment string survives; the real positive test observes the actual temp path/write. `cwd` is sealed `input/`. No shell/interpreter lookup, downloads, provider egress or helper service (`docs/DESIGN-CORE-AND-LAUNCHERS.md:985`; `docs/DECISIONS.md:736-739`; `local://t45-ruling.md:64-68,77-79`; `local://t45-api-digest.md:74,77,111`; P8/P14).

**Exact handle policy:** the request's `Stdin` and bounded stdout/stderr select a fixed allowlist consisting of **only the three child-side standard-stream handles** constructed for this run. There is no caller-extensible raw-handle list. ### 3.3. Host job, per-run job and inherited handles

**Atomic per-run Job assignment, no host breakaway (P7).** Ticket 45 does not create/replace C3's colony-wide host Job. If Core is already in a Job, the new per-run Job must be a valid nested Job under that host's constraints. An OS Job/nesting constraint is `ErrUnsupported`/native refusal before resume, never permission to disable confinement. ### 4.4. Positive closure, cancellation and timeout

**Single finalization and stop cause (P11).** One private per-run object owns the Job/process/thread, three I/O operations/buffers, timers, output cap and result. A small mutex serializes admission/finalization and freezes the returned receipt; do not hold it across a blocking native call. Late callbacks/completions refer to that same retired run, never a mutable executor-global “current output” buffer. Record the first accepted stop cause. When several conditions are already visible in one control check, use: requested `Close` → caller cancellation/deadline → monotonic wall expiry → shared output overflow → native I/O/control error; preserve other real errors by joining them. Subsequent failures do not turn a canceled/failed attempt into ordinary success. Check once more before freezing the final receipt; cancellation after that linearization cannot mutate it (`local://t45-ruling.md:55,67,77,80`; `docs/ROADMAP-CORE.md:955-959`; ticket 45 `:31`; P11).

**No-process failure.** Before a successful native creation, the module knows no child exists. On refusal/timeout/setup failure, close completed channels, write `closed/not_created`, remove only an owned profile/private files and return the real error. `TreeExited:true` then means positively no tree was created; `RootExited:false`, `ExitCodeKnown:false` and zero creation/resume times prevent a fake process receipt. A failed fence transition/uncertain local resource still quarantines. If native creation succeeded at all, even suspended with no resume, the Job/process proof below is mandatory (`local://t45-ruling.md:65,67,80`; §5 P10/P11).

**Running and natural completion.** A signaled root process is necessary but insufficient. Keep the run active while descendants are still active, even if the root exited 0 or both pipes reached EOF. Positively wait the retained root synchronization handle, capture its exit code/times, set the private observed-root-exit fact, and close owned root process/initial-thread references. Then query the retained unnamed Job's basic accounting for `ActiveProcesses == 0`. Do not keep an exited process reference forever while waiting for a counter documented to retain limit-violation references. With non-breakaway membership, no untrusted assignment handle, actual root signal and Job-zero, this is positive tree proof—not PID absence, an exit-code token, kill success, notification delivery or Job-handle signaled state alone. Poll at a 10-ms maximum observation interval using a bounded timer/native wait, never a hot loop/unbounded wait. Native exit code 259 does not make a signaled root live. Observers close their own synchronization/query handles after observation; no test holds them open through a counter-decrement assertion (`docs/ROADMAP-CORE.md:950,956,959`; `local://t45-ruling.md:67,79-80`; `local://t45-api-digest.md:99,105-108`; P7/P11/P14).

**Cancel, timeout, output/control failure, Close.**
1. Prevent new admission, accept the stop cause and mark output unpublishable. Stop forwarding stdin; request `TerminateJobObject` on the retained per-run Job. Keep the actual native return/error, but never treat the request as exit proof or use `os.Process.Kill` as the tree boundary.
2. Within one independent monotonic `StopGrace`, keep native Job/root proof checks and bounded pipe cancellation/drain active. Cancel owned pending I/O with `CancelIoEx` and observe completion; buffered bytes never bypass the shared cap. No new grace period is started by another event.
3. Capture the real root code only after its signal, then release its owned references as above. After tree proof and completed/canceled I/O, query final **Job** accounting before closing the Job. A failed *additional accounting* query makes `UsageKnown:false`/native failure and output unpublishable; it does not erase independently established exit proof or prevent safe reuse after a valid closed fence/cleanup. Read I/O through `JobObjectBasicAndIoAccountingInformation`, not the reserved `IoInfo` in extended limit information (`local://t45-api-digest.md:58-63,122`; P11).
4. Persist §5's `closed/job_empty`, then perform only bounded safe cleanup and directory flush. `ResourcesReusable:true` is last, never set merely because the tree died. An ordinary finite nonzero root exit may have `CompleteSealed` diagnostic output and `ErrProcessExit`; it is not C4 validation. Accepted cancel/timeout/overflow/native failures, cleanup-pending and quarantine always stay `Unpublishable`.
5. If the grace expires, proof fails or any native/local resource remains uncertain, freeze `Quarantined`/unpublishable/nonreusable and retain the unconfirmed fence/private data/profile. Best-effort terminate and close the non-inheritable Job/process handles safely; kill-on-last-close is an additional safety action, not a reason to clear quarantine. No retry, automatic new profile or slot reuse follows.

**Pending I/O lifetime is part of quarantine.** Never unpin/free an `OVERLAPPED`, its buffer or completion event while the kernel might still reference it. Ordinary completion/cancel joins the small pump set before cleanup; on an unconfirmed cancellation, its retiring owner retains only that operation's fixed buffer/event/native lifetime until actual completion or host-process death, with no further output mutation/publication. It may finish releasing those resources later but cannot clear the fence or admit work. Returned partial byte slices are frozen copies. This is at most the admitted run's three operations, not an unbounded retry/read queue or a background reaper service. `Close` may release the root lock once the unconfirmed fence is durable because every later `Open` must refuse it; it cannot pretend those unknown resources were freed. The executable-level crash/ambiguity drills exercise this resource boundary where practical; no fake `CancelIoEx` return is proof (`local://t45-ruling.md:55,67,80-82`; ticket 45 `:31`; P11).

**Normal result.** Only a proved closed tree, completed bounded exchange, known native accounting, durable closed fence and successful cleanup can yield a reusable final ordinary result; only root exit 0 yields nil error. The executor neither appends accepted effects nor tells a live agent anything. It returns actual native facts and private bytes; C3/C4 decide future durable operational/evidence handling (`local://t45-ruling.md:14,55,67-68`; `docs/ROADMAP-CORE.md:955`; P11).

## §5. Durable quarantine fence and supervisor-loss recovery

**Resource fence, not authority (P10).** The fence answers only “may these private native resources be reused?” It records no task, grant, command receipt, validation verdict, accepted effect or publication authority. It has no appender/catalogue/F-number, replay API or independently authoritative result store. This is the private durable quarantine state required by the ruling, with the same small atomic-file discipline as `colony.json`; nothing in this format is a frozen contract (`local://t45-ruling.md:55,67,80`; `docs/DECISIONS.md:214`; `internal/core/ledgerstore/colonyjson.go:15-47`).

**Layout and ownership.** One `Executor` owns one physical slot under its dedicated absolute `Root`; other simultaneous `Run` calls return busy rather than queue. The caller may explicitly own other independent roots, but this ticket chooses no colony scheduler or throughput/concurrency default. The host retains `durable.LockFile(Root/lock)` from `Open` through `Close`; two owners cannot sweep/reuse the same root. Root and marker/parent directories are never granted to the child; only the explicitly allowed per-run data subdirectories are. A run gets a fresh `uuid.NewV7()` identity and profile name, never a PID-derived or caller-recycled profile (`docs/DECISIONS.md:276`; `docs/ROADMAP-CORE.md:950,956,959`; `local://t45-ruling.md:55,77-80`; `internal/core/ledgerstore/store.go:239-240`).

```text
Root/
  executor.json             host-only marker: format/root_id/owner_sid
  lock                      OS lifetime lock, never inherited
  runs/
    <canonical RunID>/
      fence.json            host-only unconfirmed/closed resource fence
      fence.json.tmp        only during atomic replacement
      input/                copied regular files; read/execute only to run SID
      work/                 private run scratch, under §3/§4's chosen profile
```

`Open` accepts a new empty root (apart from its just-acquired lock) or a valid existing `executor.json` root. An unbranded nonempty directory is `ErrInvalidRoot`, never adopted or cleaned. Initial marker bytes are `{"format":1,"root_id":"<canonical UUIDv7>","owner_sid":"<canonical current Core token user SID>"}` plus LF, using the same 4-KiB/strict-key bounded decoding discipline as the run fence. The stored owner must exactly match the current trusted host's native user SID before any profile lookup/deletion/cleanup. Copying a root between Windows users is unsupported; a mismatch refuses with `ErrInvalidRoot` and changes no profile/data. This binds profile ownership to the native user as well as the unguessably fresh run name, rather than treating a copied file's `profile_created:true` as ownership in a different user context. Flush the root marker and new `runs/` directory entry before admitting work. Acquire the lock before inspecting or changing markers. A local lock refusal is busy; a malformed/reparse root/marker is invalid or quarantined, never evidence that no process exists (`local://t45-ruling.md:55,80`; P10).

**Run fence format.** UTF-8 JSON plus LF, at most 4,096 bytes, one object, no trailing data, duplicate/unknown keys or alternate numeric spellings. Emit keys in the following order; encode UUIDs by the existing canonical UUIDv7 convention. No file/body contents, environment, stdout/stderr or credentials enter it:

| Key | Exact shape/rule |
|---|---|
| `format` | Integer `1`; unknown format quarantines |
| `root_id` | Equal to `executor.json` |
| `run_id` | Equal to the canonical containing directory name |
| `profile_name` | Exactly `dwarf-harness-` followed by that run ID; not a caller-supplied lookup |
| `profile_created` | Boolean; true only after this executor successfully created and bound the fresh profile; never adoption. False requires the next three binding fields absent; true requires all three |
| `profile_path` | Absolute canonical local Windows drive path of the owned native folder, taken from its real handle; UTF-8 JSON string, no UNC/device/relative/dot-segment path |
| `profile_volume` | Exactly eight lowercase hex digits of `ByHandleFileInformation.VolumeSerialNumber` |
| `profile_file_id` | Exactly sixteen lowercase hex digits: eight-digit `FileIndexHigh` followed by eight-digit `FileIndexLow`; NTFS exercised object binding, not a content hash |
| `state` | `unconfirmed` or `closed` |
| `closed_proof` | Absent with `unconfirmed`; `not_created` only when no native process creation succeeded; `job_empty` only with `profile_created:true` and after the live positive-closure proof of §4.4 |

The 4-KiB cap and strict private version-1 encoding are P10's implementation choices, not ledger-format rules. Check the cap with a bounded read before decoding. Match root/run/profile bindings before interpreting state. A duplicate key, missing file, partial file, unknown state/proof, identity mismatch, file link/reparse point or leftover run directory without a valid fence is **quarantine**, not a clean/empty slot. Parse errors do not remove anything. Source necessity: `local://t45-ruling.md:55,67,80`; atomic-marker precedent `internal/core/ledgerstore/colonyjson.go:15-47`; D41 no false recovery `docs/DECISIONS.md:214`.

**Ordering.**
1. Validate the request and acquire the root's in-memory slot before allocating native resources. Create the unique run directory with create-new semantics, flush its entry in `runs/`, then durably publish `unconfirmed, profile_created:false`. **No profile, inheritable channel or child exists before this fence is durable.**
2. Create the fresh profile; already-existing is refusal, not derive/reuse. Obtain and verify §4.1's real native folder binding, then atomically persist `profile_created:true` and its path/volume/file ID **before** granting/staging/creating a child. Reject an encoded fence exceeding 4 KiB before launch. A crash before that transition leaves the original unconfirmed fence and quarantines. A getter/binding failure while no child ever existed may delete only the fresh profile just created by name (no untrusted code has run), never walk its unproved returned path; any uncertain deletion/fence write remains quarantine.
3. Create the actual restricted child in its per-run Job as specified in §4. Before any success/result/reuse, establish positive tree closure (or positively know no process was created). Complete/cancel owned I/O and retain the necessary native handles until that proof is recorded.
4. Only then atomically replace the fence with `closed` and its true proof. Failed/uncertain transition makes the current executor quarantine/unpublishable and leave canonical state untouched—do not assume whether replacement won. Explicit reopen trusts only the actual canonical valid closed proof for safe cleanup; an old unconfirmed/malformed/orphan state quarantines. A `.tmp` file is never proof. Nothing publishes or reexecutes on a lost acknowledgement.
5. After confirmed closure, restore the module parents' host-only DACL and safely remove private payload data; no-follow-empty the **bound, identity-matching** native profile folder, retaining the closed fence. Then close its handles and call `DeleteAppContainerProfile` for the owned name; do not delegate traversal of child links to that API. Missing bound folder skips the walk; documented already-absent deletion is idempotent. A different object at the bound path is cleanup-pending, never deleted. On native deletion failure its status is undetermined: retain closed cleanup-pending and retry only during explicit reopen, not automatic execution. Remove `fence.json` last, then the empty run directory, then flush `runs/`; release the slot only after success. Pre-marker failures retain closed; marker-gone/orphan failures quarantine; complete-directory-removal plus failed parent flush is closed cleanup-pending (`local://t45-api-digest-2.md:27-38`; P10).

Use file `Sync`, close and `durable.Rename` for every marker transition; flush a new directory's parent entry. No append-only fence log, timer recovery service or second durable result database. This is process-crash/resource fencing on the exercised Windows filesystem, **not a new power-loss guarantee** (`internal/core/ledgerstore/colonyjson.go:28-47`; `internal/core/durable/durable.go:22-24`; `docs/DECISIONS.md:419`; `local://t45-ruling.md:55`).

**Deletion tail (P10).** Windows cannot atomically delete a nonempty directory and its proof file in one filesystem operation. A crash after removing the final marker but before removing the run directory therefore leaves an orphan, and §5's conservative rule quarantines it—even though the former process knew exit. Do not “optimize” that empty directory into reusable state or preserve an ever-growing completed-run history to hide this gap. A crash after the entire directory is removed has no remaining native run resources; `Open` verifies/flushed the run-root directory before admitting new work. These are resource-fence states, not automatic reruns/results (`local://t45-ruling.md:55,67,80`; P10).

**Reopen after supervisor loss.** Under the root lock, inspect every run directory before exposing a reusable slot. Any `unconfirmed`, malformed/unknown/misbound fence or orphan directory makes `Open` return `ErrQuarantined` with the run identity when known. It starts no process, attaches to no PID, resumes no profile, emits no receipt that can publish, and does not call `DeleteAppContainerProfile` or remove that uncertain run's files. Job kill-on-last-close is a native safety mechanism, **not persistent proof that the tree exited**. PID absence, a stale PID's new occupant, profile absence, a successful kill request and a terminal root exit code do not clear the fence.

A valid durable `closed` fence is proof already established by this module before the crash. `Open` may finish only its safe, bounded cleanup; it does not reconstruct/publish output or rerun the request. Failure keeps the root unavailable; success removes/flushes that closed run before reuse. Even an existing root with no run directories must pass its `runs/` directory flush before admission, covering the completed-removal tail. There is **no force-clear/reset/retry-execution interface** in 45. Clearing an unresolved quarantine requires an explicit future trusted operational action and is not silently implemented here; the supported observable behavior now is refusal/no reuse/no automatic restart. Sources: `.scratch/dwarf-harness/issues/45-run-and-positively-close-a-restricted-windows-process-tree.md:31`; `docs/ROADMAP-CORE.md:959`; `local://t45-ruling.md:55,67,80`.

**Cleanup cannot traverse a child-created link, including the native profile.** After proved quiescence/`not_created`, use the persisted owned folder path and compare no-follow volume/file identity **before** touching it. Missing is safe to skip; mismatch refuses cleanup. A reparse root that still has the bound object's identity is unlinked, never followed; a replacement with another identity is not adopted/deleted. Walk by `DirEntry`/`Lstat`, unlink link/`ModeIrregular` entries, recurse only real directories, and never chmod an external target. Page enumeration (128 entries/read), checking the independent deadline. Close all profile storage handles before native profile deletion. Failures remain cleanup-pending (or the orphan quarantine); no take-ownership/reaper service. This deliberately avoids relying on undocumented profile-deletion traversal, and its real canary/junction proof is mandatory (`internal/core/workspace/worktree.go:236-293`; `internal/core/workspace/doc.go:855-859`; `local://t45-ruling.md:55,79-80`; `local://t45-api-digest-2.md:30-38`; P10/P14).

### 6.1. Test payloads and protected denial targets

**No mocks and no unfrozen producer payloads (P12).** All acceptance tests call `Open`/`Run`/`Close`; their executable is the actual current Windows Go test binary copied as an authorized regular input. A private `TestWinexecPayload` dispatches only when its explicit `-test.run`/argument marker is present; ordinary test discovery skips that helper. It performs real file/pipe/socket/process/Job/token syscalls, not simulated booleans. The host crash helper is a separate real process owning a real executor/root. Private phase hooks may pause/observe **after actual effects**; they do not replace Win32 procedures, fabricate failures, return pretend receipts or supply a C3 implementation (`.scratch/dwarf-harness/issues/45-run-and-positively-close-a-restricted-windows-process-tree.md:28-36`; `local://t45-ruling.md:77-82`; `internal/core/workspace/recovery_test.go:310-344,398-405,455-509`).

**Denial fixtures.**
- Build a real Git repository with the pinned real Git: a non-canonical fixture branch is checked out, then real `update-ref` creates `refs/heads/main`. Record `main`, common metadata and object/file bytes before the run. Use the existing once-per-process unregistered Git seed/private `os.CopyFS` convention; only this fixture needs Git, and it is never Git running inside the sandbox. Confirm the denied paths exist and the host can read them before the attempt.
- Create a real `ledgerstore.Create(colony, ledger.Defined())` store and `PublishBody` a known nonce; deny the actual log file, colony metadata and published body path `bodies/<first two digest chars>/<full digest>`. Record the real bytes/durable position and read the body normally from the host before/after.
- Create independent host-owned nonce files/directories for **private peers, credentials and sealed results**, plus a real test-created **owner named pipe** restricted to the Core user/SYSTEM. Their shapes are irrelevant to the executor; **only their reachability is tested**. They are not substitute grants, provider credentials, command records or publication/validation receipts, and none feeds the executor's authority/output.
- Use distinct roots/profiles for simultaneous runs A and B; disclose the other run's actual input/work paths deliberately. Secrecy of a path/name is not the access control.

The child is given the *real absolute target names*, not nonexistent paths. A host positive-control open/read (and named-pipe connection before resetting its listener) proves fixture existence/reachability for an authorized host. Denial assertions check native error class/absence of delivery and unchanged host bytes, not English messages or any generic failure. Named-pipe namespace hiding is acceptable only where the documented AppContainer namespace makes it a real isolation result and the same host path's existence was proved. On unexpected success, capture the actual native result/changed canary and fail; do not count “a syscall returned something” as denial. Sources: `local://t45-ruling.md:78`; `internal/core/ledgerstore/store.go:310-311`; `internal/core/ledgerstore/bodies.go:64-67,217,356`; `internal/core/workspace/helpers_test.go:144-180`; `docs/DECISIONS.md:2242-2247`; `.scratch/dwarf-harness/issues/45-run-and-positively-close-a-restricted-windows-process-tree.md:29-30,36`.

Give helpers finite wall/output/memory/process profiles and deterministic pipe/barrier handshakes. Read readiness from real native output or Job/process state, verify reported PIDs against the actual Job before using them for observations, and use actual synchronization handles for exit. A payload report is never the closure proof. Every helper has a host teardown that terminates/waits the actual Job/processes even when an assertion fails; normal crash rows retain no extra Job handle that would alter kill-on-close. No live provider, network service, CI credential, admin configuration or AV change is needed (`local://t45-ruling.md:67,79-83`; `internal/core/workspace/recovery_test.go:310-344,455-509`; P7/P12).

### 6.3. Crash helpers, limit failures and concurrency

**Crash boundaries (P10/P12).** Use a host supervisor helper that opens its own private root and pauses on real native barriers, prints one bounded handshake to the parent, then waits on a pipe. The parent terminates that actual supervisor and positively waits it. Each row owns its root/profile/processes; share only immutable executable bytes and an unregistered Git seed. Run independent rows in parallel only within the existing Go test concurrency, with no external test/check overlap. This is the existing C2 crash-helper pattern, not a new process-control framework (`internal/core/workspace/recovery_test.go:398-405,455-509,540-553`; `docs/DECISIONS.md:2242-2247`; `local://t45-ruling.md:80-82`).

| Death point | Required reopen result |
|---|---|
| After durable unconfirmed fence, before profile | Quarantine/no native creation; no “nothing seems live, so reuse” inference |
| After owned profile is durably recorded, before process | Quarantine; do not delete/adopt the profile on uncertain reopen |
| After atomic suspended process/Job creation, before resume | Root process really exits on supervisor/last-Job-handle loss; persistent unconfirmed fence still quarantines |
| Running with real root/child/grandchild, after readiness | Parent holds only individual process synchronization handles; all known real descendants exit after supervisor loss; reopen does not turn that external observation into a missing durable closed fence |
| After live positive tree-exit proof, before durable closed fence | Quarantine even though the test knows the old tree is now dead |
| After durable closed fence, before profile/data cleanup | `Open` may finish safe cleanup and reuse, never execute the old payload or synthesize its output. Follow it with a fresh explicit real run to prove the slot is free |
| After final closed marker is removed, before run-directory removal | Orphan run directory quarantines; no inference from emptiness |
| After entire run-directory removal, before parent flush | `Open` verifies/flushes the clean run-root and permits only a fresh explicit request, never reexecution/result reconstruction |

Use a held/blocking former payload in the final row so an attempted automatic replay would leave a real live run/busy slot or expire the explicit reopen context. Observational phase hooks may report actual native creation/PIDs; they must not stand in for process effects. Reopening stores no former request/argv/output to replay in the first place. Delayed native I/O/completion callbacks remain bound to the old private run object, never the next run's receipt/root.

**Real ambiguity and storage faults, not injected success/failure functions.**
- In the ambiguity row only, the parent intentionally duplicates the actual run Job handle before killing the supervisor. This prevents last-handle kill: verify the descendants really remain live. Reopen refuses reuse/publication/restart. Teardown explicitly terminates that Job and waits the real process handles; it does not invoke a product force-clear API.
- To fail a closed-fence replacement, hold the actual destination without delete sharing after the tree-exit barrier. The real `durable.Rename` fails; the canonical fence remains unconfirmed even if a complete closed `.tmp` exists. Release the file and verify `Open` still quarantines, never reads a temporary file as proof.
- To fail cleanup, hold a real staged file without delete sharing after confirmed exit. The canonical fence is closed, but reuse is refused until explicit safe cleanup succeeds.
- Decode/reopen corruption rows mutate one real written private fence prefix: unknown format/state, wrong root/run/profile binding, duplicate or missing key, invalid UUID, closed with no proof, `job_empty` without a created profile, partial/trailing JSON, reparse/non-regular marker. They each observe `ErrQuarantined` and preserved canaries/no execution. These are private marker regressions, not stand-in upstream event families. `FuzzFenceDecode` exercises the bounded decoder/classifier and the invariant that cleanup can be authorized only by a valid, bound closed proof; no filesystem/process work per fuzz input.

**Hard cost condition.** Every individual new top-level test and subtest stays below 60 s in the actual uncached race log. Give payloads roughly 10–15 s wall guards and short explicit stop/drain grace, with pipe/barrier readiness instead of sleeps; share fixture preparation, split genuinely different heavy resource drills into separate tests, and preserve every case if a helper is too slow. Never skip a native facility failure to make the suite green, widen `tools/check`, add `-short`, export a test-only production seam or multiply the full matrix into V5 (`local://t45-design-assignment.md:18`; `docs/DECISIONS.md:2239,2242-2247`; `local://t45-ruling.md:81-82`).

### 6.4. Defender-enabled resource evidence and cost

**Evidence is measurements, not a capacity claim (P12).** Run the focused evidence case alone on the actual Windows machine. ## §9. New numbered implementation choices

P1–P5 are settled by the gate ruling, not requests for another ruling (`local://t45-ruling.md:51-58`). The implementation choices below are proposed for the advisor; none is an owner-policy change.

### P6. One deep Core-internal module and synchronous call
- **Options:** add OS operations to the cooperative workspace layer; pre-build a C3 command runtime; or own a small `internal/core/winexec` module with a synchronous `Run` and internal native lifetime.
- **Recommend:** the third, with §3's explicit request/receipt, one OS-locked physical slot per root, immutable copied bytes and no mock/general capability backend.
- **Reason/source:** the ruling permits this in-layer producer and forbids a fabricated C3 dependency; C10's hostile-child proof is not workspace's cooperative proof. A caller can use its own goroutine without introducing a scheduler, second host or contract (`local://t45-ruling.md:12-14,55,77-80`; `docs/DECISIONS.md:276`; `internal/core/workspace/finalize.go:387-394`).

### P7. Atomic per-run Job under any existing host Job
- **Options:** create suspended then call `AssignProcessToJobObject`; break away from the host into a new Job; or atomically place the new suspended process in a preconfigured per-run Job using `PROC_THREAD_ATTRIBUTE_JOB_LIST`.
- **Recommend:** the third; never either breakaway flag. Keep the root handle until its actual exit snapshot, then close root references before the Job-zero wait; keep the unnamed Job through accounting/closed-fence durability. Refuse unsupported/conflicting nesting (§4.4).
- **Reason/source:** suspended-then-assign leaves a supervisor-death gap, while breakaway weakens the existing host lifetime. The module must survive hostile descendants and abrupt supervisor loss; the ruling explicitly asks to settle this relation (`docs/DESIGN-CORE-AND-LAUNCHERS.md:167,987`; `docs/ROADMAP-CORE.md:950,956,959`; `local://t45-ruling.md:65,67,79`; §4's native references).

### P8. Private writable scratch, bounded stdio only, no artifact export
- **Options:** read-only input and stdout/stderr with no private work root; fresh private writable work/tmp plus bounded stdio; or host/shared writable workspace/file-artifact transport and a newly engineered disk-quota mechanism.
- **Recommend:** the second. Only `input/`, private `work/` and the fresh profile's private required state are run-specific grants; `OutputBytes` caps the sole executor→Core stdio exchange. No work file is collected, accepted or disclosed; stop/cleanup fences all native writers.
- **Reason/source:** the ticket asks for permitted input/bounded output and B11's complete finite wall/CPU/memory/process/input/output profile; neither specifies a per-directory hard disk quota or a C4 artifact format. Fresh private temporary storage supports real tools without granting the live checkout/cache/home. State explicitly that scratch/profile storage is measured, **not hard disk-quota-enforced**, rather than misuse Job I/O counters or add an admin/VM/storage subsystem. C4 qualification must assess that exact profile, not assume it promises more (`docs/DECISIONS.md:736-738`; `docs/DESIGN-CORE-AND-LAUNCHERS.md:985-987`; `local://t45-ruling.md:64-69,81-84`; ticket 45 `:28-32`; §4 native references).

### P9. Complete caller-supplied finite profile with exact native semantics
- **Options:** implicit defaults/unlimited omitted fields; a generic “CPU/RAM” promise stronger than Win32 controls; or positive explicit wall/user-CPU/rate/commit/process/input/output/stop budgets with checked representation and fail-closed setup.
- **Recommend:** the third, exactly §3/§4. Deadline bounds setup and run; stop has an independent bounded grace. Use a single combined stdout+stderr cap and the explicit input-byte formula; add no arbitrary shipping defaults or hard disk quota.
- **Reason/source:** B11 names the complete finite profile and refusal if enforcement is unavailable, not physical-RAM/total-CPU/per-directory-disk promises. Later C4/R5 need an honest native profile, not an overstated receipt (`docs/DECISIONS.md:737`; `local://t45-ruling.md:68,77,81,83-84`; ticket 45 `:32`).

### P10. Small strict durable resource fence, no optimistic crash recovery
- **Options:** in-memory killed/closed flag or PID recovery; a new ledger/result-store family; or one private atomic versioned fence under each run, written before native effects and closed only after positive proof.
- **Recommend:** the third, §5's exact layout/4-KiB schema. Unknown/duplicate/misbound/partial state quarantines; a durable valid closed proof permits only bounded safe cleanup, never result replay/automatic execution. No clear/retry API.
- **Reason/source:** the ruling requires durable quarantine but explicitly no ledger family. Reuse the existing atomic-file/lock/remove conventions. Unlike `colony.json`'s optional metadata extension policy, this closed-proof parser is deliberately strict: silently interpreting a future/ambiguous key as present-day permission to reuse could release unknown native resources. This difference is confined to the security-critical private fence, not a second public contract (`local://t45-ruling.md:14,55,67,80`; `internal/core/ledgerstore/colonyjson.go:15-47,50-69`; `internal/core/durable/durable.go:5-24,32-39`; `internal/core/workspace/worktree.go:236-293`).

### P11. One final receipt after real tree proof, bounded private stdio
- **Options:** return on root exit/kill-request/pipe EOF; stream untrusted text as a new live channel; or retain native handles, bound/cancel actual I/O and return one private receipt only after closure or explicit quarantine.
- **Recommend:** the third, with §4.4's stop/finalization order and §3's orthogonal native state, outcome, output completeness and reuse flags. No output can imply validation/publication; failure preserves actual causes and positive flags only where proved.
- **Reason/source:** AC4 forbids reuse before positive tree exit and requires unpublishable ambiguity; D49 distinguishes live views from durable authority, and BD2 keeps speculative results private. Stop causes are diagnostic, not operational command receipts (`docs/DECISIONS.md:324-334`; `docs/ROADMAP-CORE.md:955-959`; `local://t45-ruling.md:55,67,77,80`; ticket 45 `:31`).
