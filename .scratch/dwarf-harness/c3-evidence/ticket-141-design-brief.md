# Ticket 141 — brief: settle billable Anthropic terminals with no output blocks (PM brief for a fresh ruling)

Ticket: `.scratch/dwarf-harness/issues/141-settle-billable-anthropic-terminals-with-no-output-blocks.md`. Base: `main` aa81bb2, worktree `C:\Users\darius.jones\worktrees\dwarf-harness\141-anthropic-zero-blocks` (branch `build/141-anthropic-zero-blocks`).

## Finding
Ticket 14's S2 review, note 1 (`local://t14-s2-review.md`, `notes[0]`), found a pre-existing defect on the Anthropic paid path; ticket 14's S3 recorded it as a limit in `internal/core/agents/doc.go:736-738`.

- `paidObservation` builds the private observation object with `MessageObjects: []ledger.ObjectRef{}` (`internal/core/agents/paid_capture.go:142`), and `paidObservationObject.UnmarshalJSON` always sets a non-nil list (`paid_capture.go:110`). `publishPaidOutputs` starts `refs := []ledger.ObjectRef{}` (`paid_capture.go:320`), so a usage result with zero output blocks stores `"message_objects":[]` in the observation object (`paid_capture.go:286-293`).
- `derivePaidResult`'s Anthropic branch then sets `v.MessageObjects = slices.Clone(o.MessageObjects)` for every non-refusal usage result without a content error (`internal/core/agents/paid_settlement.go:160-164`). With zero blocks that is a non-nil empty list.
- The frozen F3-13 check refuses it: `validPaidMessages` returns false for a non-nil empty list (`contract/ledger/paid.go:265-271`; `contract/ledger/doc.go:2343-2344`, "Object lists preserve order, are nonempty when present"), and the paid.observe/paid.correct argument check uses the same rule (`contract/ledger/paid_submission.go:104-105`, `:139-141`). `RecordPaidObservation` (`paid_settlement.go:254`, derivation at `:380-383`) returns `ErrInvalid`, and the attempt stays held at its full bound with no settlement path.
- The OpenAI branch already avoids it: `else if len(o.MessageObjects) != 0` (`paid_settlement.go:225-229`), proven by its settled zero-object rows (`paid_openai_test.go:389-391`). Ticket 14's S2 worked around the defect in a test fixture only, attesting a synthetic late text block (`paid_mixed_test.go:276-288`).
- Money-safe (over-hold) but unsettleable. A real case: an Anthropic `end_turn` (or `max_tokens`, `stop_sequence`, `tool_use`, `model_context_window_exceeded`) terminal whose `content` stays `[]`, with complete usage. The Anthropic reader completes such a stream (`internal/core/providers/anthropic_stream.go:116-119`); the test helper `paidSSE` emits one when `text == ""` (`paid_exchange_test.go:24-40`).

## Proposed choices
- **P1. Fix at the single derivation site.** In `derivePaidResult`'s Anthropic branch, set `v.MessageObjects` only when the observation lists at least one object: `} else if o.StopReason != "refusal" && len(o.MessageObjects) != 0 {`, mirroring the OpenAI branch. A zero-block result then carries a nil list, encodes without `message_objects`, and passes the frozen check unchanged. Both the live path and late evidence go through `derivePaidResult`, so both are fixed. Rejected alternative: make `publishPaidOutputs` or `UnmarshalJSON` produce nil. That would change the private observation object's bytes (`"message_objects":null` instead of `[]`), and `UnmarshalJSON` would still rebuild `[]` for every older object, so derivation would still need the guard.
- **P2. Nothing else changes.** Not `contract/ledger` (codecs, validation, goldens, doc), not the observation object's encoding, not refusal/no-charge (the billed refusal and no-charge paths already leave the list nil), the unknown/hold path, content-error `protocol_error`, corrections (they derive through the same function), nonempty output or OpenAI. No F3-13 change, so no D entry (D161) and no golden.
- **P3. Regression tests (D152; money).** Through the real boundary in `internal/core/agents`, with a loopback Anthropic SSE exchange that has no content block (`paidSSE(model, start, final, "", "end_turn", "", true)`, complete usage):
  1. Prepare → admit → dispatch → `RecordPaidObservation`: the attempt settles at exactly the profile's price of the observed usage, computed in the test from `providers.PriceHistoricalUsage` and also stated as a literal; `HeldMicros` 0; `Result.MessageObjects == nil`; `OutputStarted` false; the committed `runtime.paid_result` payload and the paid.observe submission arguments have no `message_objects` key; the budget book's settled/held totals move once.
  2. Recording the same observation again (same command ID) returns the original receipt; the durable sequence and the budget book do not move.
  3. Reopen (a fresh `Open` over the same store/root) and replay: same state, amount, nil output and released hold.
  4. One late-evidence row (`paidLateEvidence` with a complete zero-block Anthropic observation) settles the same way.
  5. Existing rows stay green unchanged: nonempty Anthropic output (`paid_exchange_test.go` complete-artifacts, `paid_blocks_test.go`), refusal/no-charge (`paid_billing_test.go`), OpenAI zero-object rows (`paid_openai_test.go`), and `TestPaidMixedProviderScopes`.
  - Rule breaks, each red on a named test then green after a byte-identical restore: (a) restore the unconditional `slices.Clone` → the new rows fail (held, `ErrInvalid`); (b) drop all message objects (`v.MessageObjects = nil` always) → an existing nonempty-output row fails; (c) record an empty non-nil list only on the late path (or on the duplicate path), if the ruling sees a separate code path worth pinning.
- **P4. Documentation.** Replace the limit at `internal/core/agents/doc.go:736-738` with one sentence: a billable, non-refusal Anthropic terminal with no output block settles with no message objects. Leave `paid_mixed_test.go`'s late-fixture workaround as is (it still proves its own rows), unless the ruling wants its comment corrected.
- **P5. One slice, S1,** in `internal/core/agents` only: `paid_settlement.go` (one condition), `doc.go` (comment) and tests (a new `paid_zero_blocks_test.go`, or rows in an existing paid test file). Focused tests, one plain verbose run of the package, gofmt, host vet and staticcheck. No local race: no locking, goroutine, channel or shared-state change. Fuzz: the PM runs `FuzzPaidGroupReplay` for 120 s at `-parallel=1` if the ruling finds its fuzzed code includes the derivation; otherwise none.
