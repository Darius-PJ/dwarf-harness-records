# Ticket 142 implementation design brief

## Owner first

Proposed, subject to the fresh advisor's ruling: use checkpointed tail reads, a complete incarnation command/identity directory, and unlocked cold preparation. Preserve frozen bytes and all authority/money/journal/recovery behavior; no contract change.

The existing LRU stays 256 entries/8 MiB, but the compact complete directory adds explicitly **linear history metadata RAM**. Four slices; preregistered decoder/hashed-byte/reopen bounds and the full four-cell matrix. Loopback/testing-only: no capacity or release claim. Sources: `.scratch/dwarf-harness/issues/142-read-only-the-ledger-tail-in-cores-agent-service.md:18-41`; `docs/ROADMAP-CORE.md:418-459`; `docs/DESIGN-CORE-AND-LAUNCHERS.md:853-859`.

## 0. Gate verdict and as-built scan map

**Gate verdict: buildable without a contract change.** The frozen reader already offers checked-close numeric reads and discardable checkpoints; those avoid prefix JSON decoding but deliberately rehash prefix bytes. No reader/scanner/store/record/golden change is proposed. Prefix hashing must remain visible in the measurement, not be called constant-total-cost. Sources: `contract/ledger/reader.go:120-193,245-345`; `docs/CURRENT-RULES.md:47-50,73-78`; `.scratch/dwarf-harness/c3-evidence/ticket-140-s6-design-ruling.json:17-30,55-75`.

## 2. Exact data, coverage, memory, locking and recovery

### 2.1 One acceleration implementation, not another authority

Extend `internal/core/agents/history_index.go`; retain its concrete private `historyIndex`, mutex, CRC/shape validation, copy-out behavior and **one 256-entry / 8-MiB charged-metadata LRU**. Put the compact complete-prefix occurrence directory alongside that LRU in the same object. The new directory is not a payload cache and does not evict individual membership facts while claiming complete coverage. It deliberately has a different, explicit **linear metadata bound** below. Do not enlarge the LRU, create a paid/loop/session cache, retain Reader/Commit backing buffers indefinitely, persist acceleration, or add configuration. Sources: P2/P3/P5; `internal/core/agents/history_index.go:136-225,261-354`; `internal/core/agents/doc.go:369-397`; `.scratch/dwarf-harness/c3-evidence/ticket-140-design-ruling.md:76-164`; `docs/DESIGN-CORE-AND-LAUNCHERS.md:853-859`.

**Private directory representation.**

- Whole-commit coverage T, known/valid flag, generation, counts and checksum; a sequence-ordered complete-commit boundary vector including genesis 0.
- Command UUID → sequence-ordered occurrence list of `{command digest, command sequence, commit first, commit last}`. Every accepted F0 command is represented, including workspace/unconsumed families. Valid history normally has one occurrence; retain conflicting occurrences rather than overwriting them.
- Closed selector kinds share the fixed-size occurrence representation: turn bound/result; tool start/result; refused effect; paid admission/intent/result/acknowledgement; and paid route configuration by exact `(RouteID,version)`. Key by the selected identity and, for journals, originating turn. Keep sequence/complete commit range, not payload/private bytes. Each relevant record creates at most four rows including alternate selector keys.
- A refused-effect tuple is installed only from an accepted zero-receipt tool result and its exact accepted start's EffectCommandID, with the result sequence. During a directory rebuild keep a temporary map of outstanding tool start → effect ID and remove it on result. A missing/mismatched start follows the existing integrity error, never invents absence.
- Protect stored row identity/range/count fields using the existing CRC convention; check coverage, boundary-vector shape/count and directory counts, requested key, row checksum and containing commit bounds before use. Damage to a row/coverage/container count invalidates the directory, not committed state. This is accidental-damage detection in private process-owned structures, not hostile same-process memory attestation, as in ticket 140/D157. No whole-history checksum computation on each hit.

These are P2/P3's representation choices; the required identities and checks come from `internal/core/agents/replay.go:318-360,424-471,505-544`, `internal/core/agents/loop_replay.go:137-248`, `internal/core/agents/loop_authority.go:76-172`, `internal/core/agents/paid_read.go:32-128`, `internal/core/agents/loop_session.go:154-181,374-468`; `docs/DECISIONS.md` — D166.

**Memory bound, not an RSS or population limit.** Let K be complete commits, H records, C command occurrences and I all stored selector occurrences. Allocate at most one boundary row/commit and at most four fixed-size selector rows/record (command rows included), so I≤4H and C≤H. Charge **96 bytes/selector row +24 bytes/commit boundary**, with O(I+K) ordinary map/slice/container overhead separately reported. No strings, JSON, private/object/body bytes or credential values in these rows. Retained payload/token entries remain ≤256 and ≤8 MiB, including the existing 128-byte entry charge and 256-byte checkpoint charge. Rebuild scratch is O(outstanding tools) plus its replacement directory; temporarily two directories may coexist. Large retained histories therefore require linear metadata RAM; do not pretend ticket 140's payload-cache bound covers it. No eviction is an admission limit: if the complete directory is discarded, coverage becomes unknown and the authoritative rebuild/fallback works. Sources: P2/P3; `internal/core/agents/history_index.go:146-180`; `docs/DECISIONS.md` — D34, B3; `docs/DESIGN-CORE-AND-LAUNCHERS.md:857-859`.

### 2.2 Building, publication, interval correctness and restart

**Open.** Start at genesis with an empty known-complete directory. For each complete commit, decode/stage its proposed occurrence additions, check supported-family command reuse against the directory covering F−1, run the unchanged reducers, then publish all projection and accelerator updates together at L.
