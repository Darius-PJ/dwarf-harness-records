## 2. Numbered choices

Each P-choice is proposed, not settled, until the advisor rules; OG choices remain the owner's even after that ruling.

### P1 — Trigger scope and race mode
Options: every branch/PR and push (duplicates checks); main pushes without race plus manually scheduled full checks (cheaper but easy to miss native race coverage); main pushes and explicit manual runs with the full check. Recommend the third: `push.branches: [main]`, `paths-ignore: ['**.md']`, plus `workflow_dispatch` with no mode inputs. Every triggered run executes `go run ./tools/check`, race enabled; no automatic PR, other-branch push, tag, schedule or `pull_request_target` run. The owner may dispatch a full run on a selected branch once this workflow exists on the default branch. Markdown-only pushes skip CI; the initial repository push contains workflow/code. GitHub's file-diff filter is capped (currently 3,000 files); a bulk push beyond that scope requires explicit full dispatch before claiming CI evidence, rather than assuming the filter evaluated every path. Local slice merges still use `-race=false` under D129; CI push granularity is separately chosen here. Batch the owner's remote pushes, not local integration checks, to contain cost. [D42; D46; TIME; A; §5; https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#git-diff-comparisons ; https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#onworkflow_dispatch]

### P2 — Smallest native runner matrix
Options: three native OS jobs or all five already-cross-built OS/architecture pairs. Recommend **`windows-2022` amd64, `ubuntu-24.04` amd64, `macos-15` arm64**, all standard hosted images. Windows 2022 avoids the documented Windows 2025/VS2026 image-mapping ambiguity; Ubuntu 24.04/macOS 15 avoid newest-image churn without choosing deprecated macOS 14. No `*-latest`, larger runner, Linux arm64 or Intel Mac in this gate. Optional native labels `ubuntu-24.04-arm` and `macos-15-intel` are considered but not admitted: three OSes meet D42 without doubling native work. Those two architectures remain native-unmeasured while the existing five import-boundary/cross-build targets remain unchanged. OS-version labels do not freeze rolling image releases or all compiler bytes; capture actual ImageVersion. [D42; A; `C:/Users/darius.jones/Documents/PROJECTS/dwarf-harness/tools/check/boundary.go:23-32`; `local://ci-facts.md:13-31,67-138` and its primary runner links]

### P3 — Checkout and Go installation (OG-DEPS)
Options: both official actions at full commit SHAs; native Git-fetch plus verified Go archives; or a hybrid. Recommend the **hybrid: pinned official checkout, direct official Go 1.27.2 archives verified by literal SHA-256 before extraction**. Keep complex token-authenticated checkout in the recorded official action; use small native download/hash/extraction steps for three fixed Go archives instead of adding setup-go and its unverified alternate go-versions distribution path. This follows D29's “small, fully specified, fully testable” exception without writing cryptography or an installer framework. Setup-go v7.0.0 is recorded as considered/not admitted: its source uses tool cache → mutable go-versions manifest/release assets → go.dev fallback, and does not compare the official archive SHA-256; its generated dist bundle was not independently audited. Go remains exactly 1.27.2 with `GOTOOLCHAIN=local`, no fallback, no tool cache reuse and no second action. All candidates' D29 records follow in §3; approval remains OG-DEPS. [D28; D29; D41; A; `local://ci-facts.md:412-476,557-559,712-746`; https://github.com/actions/setup-go/blob/b7ad1dad31e06c5925ef5d2fc7ad053ef454303e/src/installer.ts]

### P4 — Race compilers; no `tools/check` modification
Options: normalize every platform onto `DWARF_CC` and new compiler validators, or use the existing native selection. Recommend existing selection unchanged. Windows alone downloads the exact approved llvm-mingw archive, verifies its literal SHA-256 before extraction, keeps `bin` off PATH and sets absolute `DWARF_CC`. Linux already selects `/usr/bin/gcc`; macOS selects `xcrun --find clang`; both print their compiler versions. Do not set `DWARF_CC` on those hosts or download a replacement compiler. Versioned runner-image selection plus actual compiler identity is the supported Linux/macOS pin here, not a claim that those toolchain bytes never change. Extra compiler downloads or a stronger reproducible-image requirement would be new D29/owner work, not this cutover. Core/ordinary checks remain cgo-free; only checkRace sets `CGO_ENABLED=1` and `CC`. [D28; RACE; D29]

### P5 — Honest host evidence, not laptop emulation
Options: skip winexec or weaken tests on hosted Windows; reproduce laptop service/Defender exclusions; or exercise the actual hosted environment and label its evidence. Recommend the third. Capture actual Windows OS build, runner identity/architecture, effective admin status, Git and compiler versions and readable Defender status/exclusions without changing them. The AppContainer suite must run, not silently skip. Remove the two unconditional Defender claims and their now-unused constant from the resource test: those fields currently assert this laptop's configuration on every host. Preserve all behavioral assertions and historical B28/B30 evidence. Do not hard-code build 19045, user paths, exclusions, service changes or a longer grace period to obtain green CI. [A; WIN; EVIDENCE; `C:/Users/darius.jones/Documents/PROJECTS/dwarf-harness/internal/core/winexec/security_windows_test.go:41-55,83-94`]

### P6 — Optional Python/Node coverage
Options: install three additional approved/pinned graph tools; opportunistically use runner PATH; leave their explicit tool controls unset. Recommend empty `DWARF_GRAPH_PYTHON`, `DWARF_GRAPH_NODE`, `DWARF_GRAPH_TYPESCRIPT`; no separate graph interpreter/parser installation or configuration for this gate. The checkout action's Node runtime and LLVM bundle's auxiliary Python are not graph-tool configuration and must not be wired into these variables. Existing native-helper rows skip unless explicitly configured; log the three controls as intentionally empty and report that coverage absent. Runner-installed interpreters are not approved graph inputs merely because they exist. This does not skip whole graph/foundation packages. [OPT; A; D29; §3's action/compiler inventory]

### P7 — Runtime envelope and proof
Options: reuse the obsolete 20-minute package timeout, increase it again, or preserve D127 and measure hosted jobs. Recommend unchanged 30-minute per-package timeout and 25-minute escalation; a separate 90-minute job timeout bounds cold setup plus both serial test stages. `strategy.fail-fast: false` lets every OS deliver evidence even if one fails. Do not change Go parallelism, package structure, coverage, timing assertions or test cache policy to fit estimates. Hosted run durations are measurements to collect, not acceptance promises. [TIME; CHECK; `C:/Users/darius.jones/Documents/PROJECTS/dwarf-harness/docs/DECISIONS.md:2241-2243`; §5]

### P8 — Spend policy (OG-BUDGET)
Options: included-minutes-only; a $10/month cap with four total matrices; a $25/month cap with ten; or a larger budget/broader matrix. Recommend the narrow P1/P2 policy and offer **$25/month, at most ten total full matrices (eight planned pushes plus two reserved dispatches/reruns)**, priced conservatively without any free-credit assumption. **Only the owner selects or changes the dollar cap/cadence**; no budget or account-plan assumption is approved here. Each actual run consumes its own measured spend, and a slow/failing run may exhaust the cap before ten runs. §5 gives current tariffs, historical multiplier caveats and blocking controls; a YAML comment is not a hard spending limit. [A; D31; §5 billing sources]

### P9 — C3 start condition and red-run work (OG-START)
Options: workflow exists after push, regardless of verdict; or first full three-OS run passes on the exact reviewed tree. Recommend the second, but the owner decides whether red CI blocks C3. Do not silently reinterpret “remote with CI exists” as either policy. Red Linux/macOS tests are the previously deferred native C1/C2 portability evidence, not proof that a new CI workflow is broken. Record and triage each reproducible defect as narrow producer-owned repair work, preserving the original Done evidence's platform limits. C3 testing-only/D52/family gates remain independent whichever start policy the owner chooses. Its existing **exit** criterion still requires green Windows/Linux/macOS CI (`ROADMAP-CORE.md:514`); permission to start while red does not waive that exit gate. [C3; T10; PORT; D40; D52; A]

### P10 — Minimal workflow/security surface
Options: extra cache/artifact/summary/security actions and helper frameworks, or one workflow with inline host/setup commands and ordinary Actions logs. Recommend one workflow, **official checkout as its only action**, job token `contents: read`, no persisted credentials, no explicit secrets or live-provider calls, no automatic retry, no cross-run cache and no artifact-upload action. Keep failed checks red and every OS independent; never use `continue-on-error`. Logs/run URLs plus the existing check's commands, per-step timings and exit code are evidence; the PM records the exact run/commit in the existing decision/tracker documents. Native workflow-dependency lockfiles are stronger current GitHub guidance but public-preview and generated with a new `gh actions-lock` extension; do not add that dependency/tool or claim SHA pinning is the strongest available protection. The assignment's full SHA pins cover the one bundled Node action; there are no nested `uses` actions to lock. Revisit only under a separately approved change. [D29; CHECK; C3; D31; A; `local://ci-facts.md:273-341`; https://docs.github.com/en/actions/reference/security/secure-use ; https://docs.github.com/en/actions/concepts/security/workflow-dependency-lockfiles]

Do not expose the job token in this unauthenticated public-tool download. Keep the compiler off PATH. A download/hash/extraction/version failure stays red; there is no unpinned compiler fallback. [D28; P4; RACE]
