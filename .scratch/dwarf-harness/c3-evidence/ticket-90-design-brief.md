# Ticket 90 — generic Core eligibility guards

## Owner first
Ticket 90 adds a lifecycle-neutral eligibility hold to C3. It does not implement alignment, service loss, messaging or view transport. Three slices keep the contract freeze before a complete Core cutover, then prove the actual terminal surface. Coding waits for ticket 16; the advisor rules on P1–P8. No new owner authority or owner gate is proposed.

## 2. Exact contract, state and API specification
### 2.1 Agent state and authority (P1, P2)

Keep one current `eligibilityState` value on `agentState` (or its value-equivalent field in `projection.agents`), not a cache or file. Registration supplies the implicit initial value `{version:0,state:eligible,reason:none}`; old logs stay valid and Open appends no initialization. A new hold increments the agent's eligibility version and starts a stable `operation_id` equal to its command ID. Release compares **both** current version and this operation ID, increments version and retains the released operation identity for inspection. No task, message, model verdict, natural ending or financial settlement changes it. A different later hold gets a new operation identity; a late release of the old operation cannot release the new one. This implements T90:27-32 through the existing short-transition discipline (`AS/service.go:61-115`; `AS/scoped_tasks.go:86-202`; `docs/DESIGN-CORE-AND-LAUNCHERS.md:918-930`; D82/B7).

One state is intentional, not a hidden multi-cause registry. C3 holds no lifecycle prerequisites. A later authorized producer must release only after its own aggregate prerequisites permit it, using the current operation/version. Ticket 131's future pause and C8's acceptance do not become interchangeable reasons or release authorities here (T90:23,54; `.scratch/dwarf-harness/issues/131-keep-a-corps-working-while-its-officer-is-in-service-loss.md:22-33`). Concurrent independent owner edits lose by CAS rather than overwriting each other.

Use trusted **Service** methods `HoldOrdinaryWork`, `RequireFirstAction`, `DeclareNextFirstAction` and `ReleaseEligibility`; do not add these to `Agent`, the model catalogue, a grant class or the terminal command union. Like existing owner capacity/task administration, possession of the trusted Core Service seam is not an untrusted caller-supplied actor label. Each method derives the target agent's sole session and general context for its canonical command origin; caller-supplied session/actor values are not accepted. An Agent cannot set/release even its own state, and a model cannot obtain the Service seam through a tool. C8 later uses these same transitions only from its owner-authorized producer, after C8's own required human decision; 90 neither implements nor substitutes for that decision. No new owner power is proposed (`docs/CURRENT-RULES.md:38-40`; `AS/scoped_admissions.go:13-23`; `contract/ledger/doc.go:1883-1922`; D82/B7, D92 item 3 and D93 items 1–4).

Public request fields are concrete Go values, never an `any`/map argument gateway:
- Every request: `CommandID`, `AgentID`, `ExpectedVersion`; requests acting on an existing hold additionally require `ExpectedOperationID`.
- Hold: `Reason` only, valid from eligible. Require: `Reason`, `ActionID`, `FirstActionTurn`, valid from eligible or ordinary_work_ineligible without an existing declaration. From an existing hold it preserves the operation ID; otherwise it opens one.
- `FirstActionTurn`: `ContextID`, `TurnID`, `StartCommandID`, `AdmissionCommandID`, `Input session.MessageSend`, optional `TaskBinding`. Input.TurnID must equal TurnID; all IDs are distinct UUIDv7s where they identify different commands. The setter hashes the bounded supplied input but stores no input bytes and dispatches nothing.
- Next: `ActionID`, `FirstActionTurn`, valid only in first_action_required for that same action, after its currently permitted turn has a native terminal ending and (if bound) its F3-15 ending/F3-16 terminal; a recorded definite pre-admission refusal with no native work is also an ended attempt for this purpose. ContextID and optional TaskBinding stay equal to the initial declaration; only input/turn/command identities advance. It preserves the initial declaration and hold operation. This is an explicit new instruction, not a replay or a cross-context handover (`docs/DESIGN-CORE-AND-LAUNCHERS.md:833-835,918`; T90:29-30).
- Release: no reason/approval/verdict argument; valid only on a held supported state. It means this generic gate is released, not that alignment, activation, grants, capacity, service restoration or promotion was approved.

Return `EligibilityReceipt{CommandID,SubmissionSHA256,Operation,Version,OperationID,Sequence,EffectSequence}`. Version disagreement uses the existing RevisionError; wrong action/hold identity or a non-executable state edge is `ErrEligibilityStale`; malformed shape is ErrInvalid. A matching same-ID canonical request returns its original receipt before CAS; changed meaning is ErrCommandMismatch across **all** families. A distinct no-change request returns ErrNoEffect without a record. These are P1/P2's concrete API choices, following `AS/doc.go:220-233`, `AS/replay.go:672-785`, `contract/ledger/doc.go:3180-3191`.

### 2.2 Additive F3-90 wire contract (P1, P4, P5)

Add version-1 `runtime.eligibility_changed` and `runtime.eligibility_receipt`. C3 owns payloads; only `internal/core/agents` produces them through SubmitAt. Consumers are Core Open/preflight, scheduling/admission, exact-authority inspection and later C6/C7/C8 integration. Metadata only: no raw input, skill name, Purpose, private text, approval token, credential, body_refs, native handle or locator. Every known member and envelope binding is replay-essential. Add **two** catalogue entries to the count at the coder's base; do not hard-code an absolute total when 91 may land first. These are new-family rules, not modifications to F3-11/15/16 (`docs/CONTRACTS.md:117,185-210`; `contract/ledger/doc.go:3077-3093`; T90:18,22-23,27-32).

Use the existing F3-16 strict JSON discipline: 65,536-byte **whole** payload and submission bounds independently on input and compact output, including ignored extensions and the receipt's embedded submission; recursive duplicate-key refusal; UTF-8; canonical UUIDv7/nonzero digests; unsigned decimal integers through MaxInt64; checked version increment; absent optionals omitted, never null; unknown optional keys ignored and excluded from canonicalization; ErrInvalid on malformed known values. **State is the closed set eligible/ordinary_work_ineligible/first_action_required** (P1); an unknown state fails decoding/Open, never dispatches or becomes eligible. `reason`, `refusal.code` and receipt outcome are open `[a-z][a-z0-9_]*` tokens ≤64 bytes. Initial documented reason values are `none`, `explicit_hold`, `first_action`; receipt writers emit `recorded`; refusal writer codes are below. Eligible uses reason none; held states require a non-none reason. Any well-formed non-none owner/producer reason is permitted, so a later producer adds its documented reason additively without changing a closed set. An unfamiliar reason never lifts a hold. The reason/outcome convention follows `contract/ledger/doc.go:3089-3095,3132-3150`, D165/D169 and T90:54; the finite three-state selection is P1.

Exact compact member order:
```text
runtime.eligibility_changed:
  expected_version, version, state, reason, operation_id, first_action?
first_action:
  action_id, initial_turn, permitted_turn, refusal?
initial_turn / permitted_turn:
  context_id, turn_id, start_command_id, admission_command_id,
  input_sha256, task_binding?
task_binding:
  task_id, assignment_id, generation
refusal:
  turn_id, start_command_id, stage, code
runtime.eligibility_receipt:
  command_id, submission_sha256, submission, outcome, effect_sequence

canonical submission:
  schema («SCHEMA-90»), actor, origin, operation, expected_version,
  expected_operation_id?, arguments
```

Submission actor and operation are closed. Operations and exact concrete argument order:
```text
eligibility.hold           owner  {reason}
eligibility.require_first  owner  {reason,action_id,turn}
eligibility.first_next     owner  {action_id,turn}
eligibility.release        owner  {}
eligibility.first_refused  core   {action_id,turn_id,start_command_id,stage,code}
turn: same FirstActionTurn binding order as above (digest only, no Input)
```
`expected_operation_id` is required exactly when mutating an existing held operation (require_first from ordinary hold, first_next, release, first_refused); it is absent for a new hold/require from eligible. Expected version 0 is the implicit eligible state; later expectations are positive. The changed record is a full snapshot derived from the command and preceding state, not trusted caller state. `first_action` is required in first_action_required, absent on an initial ordinary hold; release retains its prior declaration/refusal metadata as history, not authority, and uses reason none. A subsequent hold from eligible clears that prior declaration. Initial turn never changes within an ActionID; permitted turn initially equals it and changes only at first_next, which clears its prior refusal/current-attempt source metadata but preserves first-admitted identity. All versions increment exactly once per recorded change. Require-first/next validate registered same-agent context, exact task/assignment if present, unused turn/command identities and no pre-existing work under them; next also preserves initial context/task binding. Known argument members belonging to another operation are forbidden, even null. No digest is permission. P1/P4 follows T90:27,29-31 and `AS/loop_start.go:69-78,119-139`; version/identity rules mirror `contract/ledger/doc.go:3195-3218`.

Every operation is exactly `[ledger.command, runtime.eligibility_changed, runtime.eligibility_receipt]`, one SubmitAt planned at a current tail, three moved-tail attempts then existing BusyError{ledger_tail}. No mixed-family commit. Command/receipt actor equals submission actor; change actor is core; every envelope has the derived target-agent/general-context origin, no TurnID, and envelope operation_id equal to this command ID. Payload operation_id instead identifies the held operation as §2.1 defines. Receipt effect_sequence names the actual change after authoritative readback; the embedded normalized submission re-encodes to submission_sha256. Prepare, decode, plan, stage and install atomically before p.through moves; invalid groups install nothing. Earlier bytes, group shapes and goldens stay byte-identical (`AS/replay.go:463-670`; `contract/ledger/doc.go:3167-3191`; `docs/DESIGN-CORE-AND-LAUNCHERS.md:851-861`).

`eligibility.first_refused` is an **unexported Core observation**, not a permission change. It is legal only for the current exact declaration and before that turn's first committed paid intent. Its closed stage is `turn_admission` (no native admission or loop binding) or `paid_admission` (a verified loop binding exists, but the first paid admission/preparation/send is definitely refused before intent). It leaves state, reason, hold/action/turn identities unchanged and stores the normalized refusal code. Codes written are `denied`, `busy`, `unavailable`, `invalid_argument`, `too_large`, `integrity`, `ledger_tail`. Do not store error strings, private paths, raw exceptions, money or credentials. Duplicate identical current refusal produces no record. Native admission supersedes a turn_admission refusal; a paid_admission refusal stays visible until an intent or an explicitly permitted next turn supersedes it. A later result after an intent is ordinary result/settlement evidence, never an admission-refusal record. Core rechecks the stage/absence of intent at the committing prefix, so a late refusal cannot relabel sent work. Persistence uncertainty returns the real persistence failure, never a claimed durable refusal. This P5 choice satisfies T90:29's visible refused admission using the one-authority recording pattern (`AS/doc.go:220-233`; `AS/replay.go:463-670`; `AS/loop_continuation.go:101-176`).
The live observer belongs in the existing runtime error/stop chain, not inside a pure planner or while holding a lock: before the first intent, `noteStop` observes an actual authority_lost/integrity pre-dispatch refusal as paid_admission/denied or integrity; `quantum` observes the original normalized preparation/admission error before its ordinary wait/stop handling. Cancel/shutdown/deadline/loop-limit are not admission refusals. A release/next/intent that wins first makes the old observation stale and it writes nothing; return the actual current outcome, not a fabricated persistence failure. No hot eligibility scan or loopBoundary return-type migration is needed (`AS/loop_runtime.go:190-192,447-498,521-609`; `AS/loop_continuation.go:101-176`; P5).


### 2.3 The exact first-action entrance (P3–P5)

Hash this stable, compact request preimage using the existing JSON escaping and digest conventions, with this key order:
```text
{schema:1,origin:{agent_id,session_id,context_id},command_id,turn_id,
 text,artifacts,task_binding?}
```
`command_id` is the declared StartCommandID; nil artifacts normalize only to `[]`; preserve the supplied artifact order, do not sort or rewrite text. `task_binding` is the declaration's optional exact binding and must match the configured loop context. The setter and start verifier use one helper so they cannot disagree. This is the selected **owner input**, not a prompt string, actual C9 pin, rendered request hash or S4 passive-notice selection. Those existing private input/render objects remain authoritative for the actual turn; S4 schemas 1/2 continue unchanged. The exact identity requirement comes from T90:29-30 and `docs/ROADMAP-CORE.md:425`, the separation from real pins from `docs/DESIGN-CORE-AND-LAUNCHERS.md:833-837`.

The existing Session `message.send` is the only bound-loop start entrance needed. Derive its principal/origin normally. Before preparation or native admission, classify it under Service.mu:
- Eligible: existing behavior, no first-action shortcut.
- Ordinary held: typed EligibilityHeldError, no retained input or latent start.
- First required: only the exact ContextID/TurnID/StartCommandID/input digest/TaskBinding may enter. For that request use the **declared AdmissionCommandID**, not the fresh UUID currently minted at `AS/loop_start.go:166`. No caller `first=true` flag or role title is accepted.
- Same-ID bound retry: return the old binding/result after current disclosure authorization, never enqueue another turn or run grant/budget admission again. It remains a retry even if the agent is now held under a later operation. Current eligibility still governs any new dispatch of the existing live turn.
For exact first starts, join concurrent duplicate submissions through a small `firstStarts` map keyed by StartCommandID under runtime.mu. One leader runs admission/render/bind/initialize; same-origin/same-digest followers wait on its shared completion channel **outside every lock/gate**, honoring their own context, and return the copied outcome. A changed identity/digest under the live key is ErrCommandMismatch. Remove the entry and close its completion on every leader exit, including definite refusal; it retains no refused request and a later retry is explicit. One entry exists per live declaration/start call, not per dormant agent; it launches no goroutine and is not a scheduler queue. Use ordinary native/bind global receipt checks before any re-execution. Never hold the context gate across Agent.StartTurn: it already acquires agent then context gates (`AS/scoped_execute.go:264-279`). This P6 choice closes the admission→bind race without a gate re-acquire or weakening the native boundary (`AS/loop_start.go:166-255`; `AS/doc.go:1057-1070`; T90:30).


The native Agent.StartTurn guard independently checks `(origin,TurnID,AdmissionCommandID,TaskBinding)` for this exception.
