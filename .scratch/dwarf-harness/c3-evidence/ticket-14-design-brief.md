## 0. Scope and reuse map
This adds the second real adapter to ticket 13's **existing safe static paid path**, with the authorized OpenAI drill after local proof. It does not add a running turn/tool loop, retry scheduler, R0/R1 dependency, capability-discovery service, provider wallet, invoice cap, production delivery or C3 completion. Main's TURNS receives the same callable Core baseline, not a new CLI or launcher protocol. All workloads and the drill remain testing-only. Sources: T14:11–39,43–48; `docs/ROADMAP-CORE.md:420,431–446,462`; `docs/DECISIONS.md:3193–3198`.

### 3.1 Complete order and authority

1. Owner explicitly installs current route/profile, binds a fresh provider-matching credential version and configures enabled terms; existing `external/model.call` grant names `paid-route/<UUID>`. No provider/model default or implicit credential selection.
2. Host preparation validates origin/turn/task/route/version, samples shared trusted clock, verifies profile and live authority; reserves process/preparation bytes **before** copying/compiling. OpenAI size bound accounts for all strings/raw JSON/escaping using the existing conservative 6× structural allowance; reserve the existing `20×bound + 10 MiB`, not merely wire length. Serialize once, reject pinned secret in decoded input, seal exact provider headers/body, quote and recheck before returning handle.
3. `AdmitPaid` repeats current authority, task, route/profile, credential version, expiry, exact seal/quote and all-scope capacity; publish exact body then commit one existing admission group/full hold. Failed admission sends nothing.
4. `DispatchPaid` reserves from the **same** `MaxActivePaid`/physical-byte pool and borrows pinned bytes; under lock repeat all guards, cap exposure counted once, commit durable intent. Only this invocation's fresh committed effect permits the POST. Never replace the configured authority with an arbitrary input URL.
5. Outside lock, same transport sends sealed bytes once; select parser by the admission provider; publish observation/output only into original context. Return intent receipt plus opaque observation. Host then supplies a fresh result CommandID to `RecordPaidObservation`; price from admission profile without credential/live clock. Handle/idempotent receipt is never a new send permit.

These are preserved ordering guarantees, with a second compiler/parser branch, not new policy. Sources: `docs/DESIGN-ROUTING-LAYER.md:254–270,890–914`; `internal/core/agents/doc.go:464–545`; `internal/core/agents/paid_prepare.go:71–218`; `internal/core/agents/paid_dispatch.go:16–200`; `internal/core/agents/paid_settlement.go:96–172`.

### 3.2 Shared concurrency and scope arithmetic

Keep one `paidRuntime` prepared/call/exchange set and one `budgetBook` across both providers. No per-provider lock, copied allowance, separate active-call limit or credential-borrow serialization. Existing `Secret.WithBytes` permits concurrent borrowers; rotation/revocation becomes durable before waiting for borrowers. Every attempt atomically checks the sorted de-duplicated colony, originating agent, provider credential scope, task where applicable, leaf grant and **every ancestor**. Credential scopes may differ; colony/agent/common grant ceilings remain shared. Delegation reserves no capacity. Admission with another sibling's hold therefore competes, not double-spends.

Preserve `occupied(s,P)=settled(s,P)+all unresolved holds(s,any period)`, duplicate/evidence inertness, original-period late settlement/correction, exact unclamped actual costs and intersecting-scope fences. A new provider's configuration never implies a global account/invoice cap; same key in another colony is outside this book. Explicit retry uses new attempt/preparation/admission and fits beside unknown holds; no retry-specific scheduler or convenience API. Sources: T14:38–39; `internal/core/agents/paid_budget.go:60–150`; `internal/core/agents/doc.go:437–480,594–625`; `internal/core/credentials/doc.go:14–21`; `docs/DESIGN-ROUTING-LAYER.md:899–914`.


## 4. OpenAI request compiler and refused variants
**P3 — supported static subset.** `CompileOpenAI(Profile, Request) (Compiled,error)` reuses the canonical `Request` and strict `ParseRequest` (no raw vendor-body entrance). Require an OpenAI profile; `16≤Request.MaxTokens≤profile.OutputMax`; nonempty messages ending in user; only user/assistant messages of nonempty text blocks; optional `System` text; optional locally defined function schemas; tool choice auto/none only. Reuse existing UTF-8, duplicate-key, depth, visible name/ID and 512 KiB request guards, owned deep copy and deterministic JSON escaping. OpenAI rejects every Anthropic `CacheControl`, prior `tool_use`/`tool_result` block and any extra populated field inconsistent with a text block before admission/send. No artifact-driven continuation/tool loop is claimed in this ticket. Sources: OF:62–82,305–327; `internal/core/providers/anthropic.go:12–58,88–124,128–278`; T14:29–31; R13 P15; P3.

Serialize exactly once, compact `encoding/json`, in this order:

```text
model, max_output_tokens, input, stream, store, service_tier, truncation,
background, include, prompt_cache_options, instructions?, text,
tools?, tool_choice?, parallel_tool_calls?
```

Values: model from pinned profile; `max_output_tokens=Request.MaxTokens`; `stream:true`, `store:false`, `service_tier:"default"`, `truncation:"disabled"`, `background:false`; `include:["reasoning.encrypted_content"]`; `prompt_cache_options:{"mode":"implicit","prewarm":false,"ttl":"30m"}`; `text:{"format":{"type":"text"}}`. `input` preserves message/block order as `{type:"message",role,content:[{type:"input_text",text}]}` for **both** user and assistant input. `instructions`, if System is nonempty, joins its text blocks with `\n\n` in order, with no provider cache markers. No timestamps/random IDs/selected-view state enter the body. Sources: OF:60–86,287–325; `docs/DESIGN-ROUTING-LAYER.md:254–270`; P3.

Each local tool is `{type:"function",name,description?,parameters,strict:false}` in caller order; names unique under the existing canonical name grammar; parameters are complete duplicate-free bounded JSON objects with root `type:"object"`, not a hosted/custom/MCP tool. Description is omitted only when empty. With tools, `tool_choice` is the explicitly validated auto/none value (canonical nil maps to auto, as Anthropic does) and `parallel_tool_calls:false`; without tools omit all three and reject a supplied choice. Keep the allowed tool names privately in `Compiled` for returned function-call validation; they confer no tool execution authority. Returned `{type:"function_call",call_id,name,arguments:<JSON string>}` maps to canonical `local_tool_call` only for a declared name, unique valid call_id, status absent or `completed`, async absent/false, caller/namespace absent/null, and arguments decoding to a complete strict JSON object. Use `call_id`, not output-item `id`, as the call identity. An incomplete/malformed/unknown tool produces no canonical command; independently complete usage can still settle. Sources: OF:68–70,311–325; `internal/core/providers/anthropic.go:99–114,128–278`; `internal/core/agents/doc.go:557–565`; P3/P6.

Refuse before send: a model outside §6's allowlist; any other host/path/region/tier/header; omitted/implicit model; automatic tier; store/previous-response/conversation/background state; input images/audio/video/files/PDF/media; hosted web/search/shell/code/container/MCP/custom tools or nested iterations; compaction/configuration-update; JSON/schema output, sampling/effort/pro-mode knobs, logprobs, metadata and request-supplied org/project; prewarm/comparison diagnostics/explicit cache breakpoints/12h or legacy retention controls; all raw/opaque/provider-reasoning input and prior structured function history. These are a deliberately bounded supported subset, not claims that those vendor features are nonexistent. Encrypted reasoning **output** and response IDs are retained with the initiating context, but never substitute for locally authorized canonical history. `store:false` avoids stored-response dependency; it is not a no-retention/zero-cache promise. Sources: T14:29–31,35; OF:44–48,62–86,192,236–250,287–325; `docs/DESIGN-ROUTING-LAYER.md:687–704`; P3/P4.


## 5. Stream parser, evidence and honest settlement states
### 5.1 Parser and provider-neutral evidence interface (P5)

Add `ReadOpenAIStream(io.Reader, Profile, Compiled) (StreamResult,error)` and `ReadOpenAIResponse(*http.Response, Profile, Compiled) (ResponseEvidence,error)`. Retain existing outer interfaces; extend `StreamResult` only with optional raw `ServedTier` and `ToolUsage` JSON. Core's observation gains matching OpenAI-only `served_tier?`, `tool_usage?` immediately after `stop_details`, omitted for Anthropic so its existing object bytes stay unchanged. `StopReason` is the explicit terminal response status; `StopDetails` is the exact `incomplete_details` value when supplied. `MessageID` is Responses `response.id`, not an item ID; `Model` must equal the pinned model. `Complete` means a validated terminal response was received, **not** a successful model answer. Sources: OF:92–96,158–174,182–200; `internal/core/providers/anthropic_stream.go:38–58`; `internal/core/agents/doc.go:567–583`; P1/P5.

Use the existing bounded SSE framing reader (BOM/UTF-8, CR/LF/CRLF, comments, multiline data, blank-line event termination); never reconnect for `id`/`retry`. Keep its 1 MiB event/line, 16 MiB entity, 8 MiB output, 262,144 events and 256 item limits, recursive duplicate-key/depth-64 checks and before-retention bounds. HTTP 200 requires UTF-8 `text/event-stream` and no unsupported Content-Encoding; HTTP errors have bounded ≤64 KiB strict JSON capture. Exceeding a capture/private-object limit yields the existing fixed nonsecret unknown observation/full hold, not a successful truncated result. These are inherited producer resource limits, not endpoint token limits or new performance targets. Sources: `internal/core/providers/anthropic_stream.go:14–21,91–209`; `internal/core/providers/response.go:52–101`; `internal/core/agents/doc.go:562–583`; T14:37.

The API does **not** specify a universal add/delta/done order or promise that every lifecycle snapshot is cumulative. Therefore do not import Anthropic's state ordering or add lifecycle usage snapshots. Recognize the text/function/reasoning/refusal/lifecycle events listed in OF:92; parse their bounded typed metadata for identity/output witnesses, but construct canonical output and billable usage from the explicit terminal `response` object only. Intermediate snapshots replace the previous diagnostic snapshot; never append a snapshot's full text to already seen deltas. `RawUsageStart` is the first response usage value, `RawUsageFinal` the terminal value (null/absence preserved), and `RawUsageMerged` a copy of the terminal usage object only. No stale counter is carried into partial terminal usage. Sources: OF:94–96,100–174,182–186; T14:37; P5.

Require each known event's `type` to match its explicit SSE name if a name is supplied; validate sequence numbers as nonnegative integers and strictly increasing when present (gaps allowed; no invented contiguous/zero-start rule). Track response identity and any item index→ID association that is present; conflicts are protocol errors, not retargeting. A validated terminal can supply all output without requiring every illustrative added/done event. `response.completed`, `response.incomplete` and `response.failed` must agree with their response status and the previously observed response/model identity; only the first valid terminal decides final usage. Once it is fully framed and validated, stop reading/close the body; EOF is not needed for finality, and no new network call follows. Unknown event types are bounded/deduplicated diagnostics and make interpretation unknown/held rather than guessing harmlessness; unsupported hosted/media/compaction events or output kinds likewise retain exposure and flag a profile violation. This conservative sequence/unknown-event policy is a P5 choice, not a claimed vendor guarantee. Sources: OF:92–96,158–176; `internal/core/providers/anthropic_stream.go:125–209`; T14:31,37; P5.

### 5.2 Exact usage and held/settled states
Route existing `NormalizeUsage`, `NormalizeSealedUsage`, `Bound`/`BoundHistorical` and `PriceUsage`/`PriceHistoricalUsage` through the supported provider/usage-schema interpretation. Anthropic's five-class results and pricing stay intact. For OpenAI, output dimensions contain both recognized output-band classes; all eight exact classes and `default_short`/`default_long` with raw served `default` are validated on live derivation **and ledger replay**, not just at the stream parser. OpenAI requested output below 16 cannot produce a supported quote. Late observation/correction derives counters afresh from `RawUsageFinal`; it must not trust a divergent/stale `RawUsageMerged`. Add the provider sentinel `ErrTariffAmbiguous` for P9, returned without a bound violation, so parser/Core can retain the explicit `threshold_ambiguous` diagnostic and the full hold. Other incomplete usage uses existing usage errors. Source: `internal/core/providers/{money.go:141–198,usage.go:80–114,206–269}`; `internal/core/agents/{paid_attempt.go:31–70,311–384,paid_settlement.go:69–161}`; OF:66,182–200,331–333; P1/P2/P5/P9.

Output evidence is monotone: any nonempty text/refusal/function/reasoning delta, begun output item, or terminal positive inclusive output witnesses begun output; later empty snapshots/corrections cannot erase it. Canonical text requires a terminal assistant `message` with completed status and only valid `output_text` parts; unsupported annotations/content kinds invalidate canonical output, without erasing independent complete usage. Terminal reasoning items are preserved as complete opaque JSON as OF:327 describes; terminal incomplete output never becomes a completed tool command. Unknown/hosted billable events, nonempty tool usage or contradictory positive units flag profile violation; mere missing final usage retains a hold without inventing an overrun. The parser's sequence/identity policy never attributes by the launcher's current selection. Sources: OF:92–96,158–200,307–327; `internal/core/agents/doc.go:529–536,557–583`; T14:35–39; P5/P6.


For a supported terminal, require nonnull plain nonnegative int64 `input_tokens`, `output_tokens`, `input_tokens_details.cached_tokens`, `input_tokens_details.cache_write_tokens`, plus actual `service_tier:"default"`. Let `I=input_tokens`, `R=cached_tokens`, `W=cache_write_tokens`; require `R+W≤I` using big integers and normalize **uncached = I−R−W**, cached=R, write=W, output=`output_tokens`. `output_tokens_details.reasoning_tokens`, when present, must be nonnull/nonnegative and ≤output, but is never added. `total_tokens`, when present, must equal input+output; neither this derived consistency counter nor an omitted reasoning breakdown creates a second price dimension. A missing/null cached/write counter is not guessed zero: automatic caching is possible. Unknown nonnull usage dimensions or a nonempty `tool_usage` object are unsupported/held. Raw fields remain available in the protected observation. Sources: OF:182–186,192,200,236; T14:36–37; P2/P5/P6.

Complete final reported billable units are accounting evidence, not an invoice claim. Unknown holds survive restart/period rollover; explicit later evidence/correction uses original context/profile/period and no present-day credential. OpenAI profiles carry no no-charge rule, so Anthropic's refusal rule is never reused. Unknown/refused/malformed content never becomes successful text; financial usage remains independent. ## 6. Pinned tariff profile and inclusive maximum
### 6.1 Exact representation (P2)

Keep schema-1 `Profile`/`Tariff` encodings and digest orders. OpenAI's versioned usage-schema meaning partitions each class by the guarded inclusive-input threshold policy P9 below. Exactly eight sorted rate/usage-class tokens are used: `input.cached.long`, `input.cached.short`, `input.uncached.long`, `input.uncached.short`, `input.write.long`, `input.write.short`, `output.generated.long`, `output.generated.short`. Cached and write units are disjoint subsets of inclusive input. All eight classes occur exactly once in normalized `PaidUsage`; the inactive band has zero units, never an additional copy of usage. `pricing_tier` is exactly `default_short` or `default_long`; `served_tier` separately records the provider's raw `default`. The threshold guard and wire-usage interpretation are immutable properties of `openai-responses-text-30m-kguard/v1`, not reparsed from source prose. Sources: T14:36; `contract/ledger/doc.go:2335–2342,2364–2377,2389–2430`; OF:331–333; P2/P9.

Tariff rates are already the exact applicable model/region/served-tier rates, including any regional multiplier, for **each band**; no runtime lookup of today's prices and no floating multiplier. Tariff digest pins all eight rates; full profile digest pins usage schema, model, region, tier, maxima and source verification. No new unhashed threshold or sidecar. Source-verified positive integer inclusive bounds and every applicable rate are required before live installation. Existing host-trusted source verification remains explicit: a quote string is provenance, not automatic authentication of a provider fact.
