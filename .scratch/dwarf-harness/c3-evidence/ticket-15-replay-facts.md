## 2. Anthropic Messages: thinking with tool use

**NEW 6 / SAME 2 / CHANGED 0 / UNVERIFIED 1**

- **SAME — existing model configuration.** The current model-specific thinking settings for Opus 5.5, Sonnet 5.5, and Haiku 4.5 are recorded in `local://t13-anthropic-facts.md:180–194`.
- **SAME — manual versus adaptive forced-tool behavior.** The existing digest records the rule: “Forced tool use (`tool_choice: {"type": "any"}` or `{"type": "tool", ...}`) is incompatible with manual extended thinking but works with adaptive thinking.” (`local://t13-anthropic-facts.md:180`.) The current guide likewise says manual thinking permits `auto` or `none`, while adaptive permits forced tool use except on Opus 5.5, Sonnet 5.5, Fable 5.1, and Mythos 5.1. ([`thinking.md`](https://platform.claude.com/docs/en/build-with-claude/thinking.md):940–941; retrieved 2026-10-30 16:04:39–16:12:45 EDT.)
- **NEW — tool-use turn blocks must be replayed intact.** “When you return tool results, you must pass the thinking blocks from the assistant message back to the API, complete and unmodified.” Within the latest assistant message, “the sequence of consecutive `thinking` blocks must match what the model generated in the original request: you can’t rearrange, edit, or partially drop them. This includes `redacted_thinking` blocks.” Modified blocks are rejected with 400, subject to the documented exception for text in the empty `thinking` field of an omitted block. ([`thinking.md`](https://platform.claude.com/docs/en/build-with-claude/thinking.md):940–984; retrieved 2026-10-30 16:04:39–16:12:45 EDT.)
- **NEW — redacted blocks and signatures.** “A `redacted_thinking` block contains encrypted thinking content in a `data` field, with no readable text.” “The `data` field is opaque and encrypted. As with the `signature` field on regular thinking blocks, pass `redacted_thinking` blocks back to the API unchanged” when continuing a multi-turn tool conversation. ([`thinking.md`](https://platform.claude.com/docs/en/build-with-claude/thinking.md):1199–1218; retrieved 2026-10-30 16:04:39–16:12:45 EDT.)
- **NEW — signature/prefix invalidation.** “The top-level `system` prompt, `tools`, and `messages` before the block are its prefix. If the prefix differs from what you sent when the block was produced, that block and every later thinking block fail the prefix check.” The page separately says a tampered or undecryptable signature “always returns a 400 error.” Prefix-mismatch handling is account/configuration-dependent; the page documents a beta control for choosing `error` or `drop_block`. ([`preserved-thinking.md`](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking.md):29, 145–156; retrieved 2026-10-30 16:04:39–16:12:45 EDT.)
- **NEW — completed prior turns and model difference.** “Allowed: outside tool use, omit prior turns’ thinking.” The model table says Opus 4.5 and later Opus, Sonnet 4.6 and later Sonnet, and Haiku 5.5 “Keep all prior turns”; all Haiku models through Haiku 4.5 “Keep the last turn only.” For the latter, “When you pass older thinking blocks back, the API strips them automatically.” ([`thinking.md`](https://platform.claude.com/docs/en/build-with-claude/thinking.md):978–984, 1092–1093; retrieved 2026-10-30 16:04:39–16:12:45 EDT.)
- **NEW — replay token accounting.** For keep-all models, “retained thinking blocks count as input like any other conversation history.” During a tool-use loop, cached thinking blocks “count as input tokens in your usage metrics when read from the cache.” ([`thinking.md`](https://platform.claude.com/docs/en/build-with-claude/thinking.md):1092–1093; [`thinking-steering-and-cost.md`](https://platform.claude.com/docs/en/build-with-claude/thinking-steering-and-cost.md):1128–1165; retrieved 2026-10-30 16:04:39–16:12:45 EDT.)
- **NEW — interleaving and Haiku 5.5.** “With adaptive thinking, interleaved thinking is automatic on every model that supports adaptive thinking. No beta header is needed.” The explicit supported-model list includes Opus 5.5 and Sonnet 5.5; the page says Haiku 4.5 “does not support interleaved thinking.” Manual extended-thinking interleaving requires a beta header and changes budget counting. Current configuration table lists Haiku 5.5 as adaptive and Haiku 4.5 as extended thinking. ([`thinking.md`](https://platform.claude.com/docs/en/build-with-claude/thinking.md):87, 101, 1004; retrieved 2026-10-30 16:04:39–16:12:45 EDT.)
- **UNVERIFIED — Haiku 5.5 interleaving.** The current interleaving paragraph does not list Haiku 5.5 among its explicitly named models, nor say it is unsupported. The checked text therefore does not confirm whether Haiku 5.5 supports interleaving.

([Responses reference](https://developers.openai.com/api/reference/resources/responses/index.md):3674–3719; retrieved 2026-10-30 16:04:39–16:12:45 EDT.)

## 5. OpenAI Responses: `function_call` and `function_call_output`

**NEW 3 / SAME 1 / CHANGED 0 / UNVERIFIED 3**

- **SAME — schemas and existing limits.** The existing digest `ticket-14-openai-facts.md:325` records the call and output schemas: `FunctionCall` has string `arguments` (JSON-encoded), `call_id`, `name`, and `type`; `id` and `status` are optional. `FunctionCallOutput` has `output`, `type`, optional `call_id`/`name`/`status`, and the existing string-size limit. Current reference likewise gives `FunctionCallOutput.call_id` as optional in the schema. ([Responses reference](https://developers.openai.com/api/reference/resources/responses/index.md):1123–1189, 1351; retrieved 2026-10-30 16:04:39–16:12:45 EDT.)
- **NEW — matching and one output per requested call.** “When the model calls a function, you must execute it and return the result.” The guide says responses may include “zero, one, or multiple calls,” and each function-call entry has a `call_id`, `name`, and JSON-encoded `arguments`. Its example appends each `function_call_output` using the call’s `call_id`. ([`function-calling.md`](https://developers.openai.com/api/docs/guides/function-calling.md):603–607, 645–657; retrieved 2026-10-30 16:04:39–16:12:45 EDT.)
- **NEW — output content forms and documented size fields.** The reference allows `output` as a string or an array of text, image, or file content; its string form has `maxLength: 10485760`, and a text content part also has `maxLength: 10485760`. ([Responses reference](https://developers.openai.com/api/reference/resources/responses/index.md):1189–1215; retrieved 2026-10-30 16:04:39–16:12:45 EDT.)
- **[INFERENCE] — observed order in the guide's sample.** The sample first appends `response.output` to input, then loops over calls and appends each matching output. This example places call items before their outputs; it does not specify a normative ordering rule among outputs for parallel calls. ([`function-calling.md`](https://developers.openai.com/api/docs/guides/function-calling.md):645–657; retrieved 2026-10-30 16:04:39–16:12:45 EDT.)
- **UNVERIFIED — missing/unmatched output error.** The checked function-calling and error documentation does not state a specific HTTP status or error message for a missing or unmatched `function_call_output`.
- **UNVERIFIED — strict parallel-result order.** The documentation example shows outputs appended during a loop, but does not specify whether output items for parallel calls must follow call order or may be reordered.
- **UNVERIFIED — aggregate array limit.** The reference gives string and text-part `maxLength` fields but no overall cap for a content array or its aggregate size in the checked schema.
