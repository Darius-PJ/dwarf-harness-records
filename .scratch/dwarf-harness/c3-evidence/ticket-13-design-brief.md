### 2.2 Credential scope, version and lifetime (P3–P4)

`credential_scope_id` is a Core UUIDv7 for one owner-declared provider account/allocation **within this colony**; it is neither an API key hash nor a global account guarantee. Rotated keys for that allocation share it. Owner `BindCredential` names provider, scope, new UUIDv7 credential version and an opaque Core-configured `source_id` selecting exactly one environment-variable name or native-store target. Resolve that source once into bounded private memory, validate nonempty/header-safe bytes, record only provider/scope/version/source-kind/source-ID metadata. Command hashing includes source ID, never secret/locator, so changing sources cannot reuse a command meaning. No secret-derived fingerprint, auth bytes/value/size, native target, environment value or credential error text enters a hash/record/fixture/log/receipt. Locators remain Core host configuration, not agent data. Sources: `docs/ROADMAP-CORE.md:434,491`; `docs/DESIGN-CORE-AND-LAUNCHERS.md:146-162,930,1000-1008`; `docs/DESIGN-ROUTING-LAYER.md:216-266`; ticket 13:28,30; P3.

`BindCredential` rotation creates a **new immutable version**; it never mutates the bytes of an existing version. The owner may keep the old version authorized until explicit `RevokeCredential`, or revoke it in the same rotation command by naming `revoke_previous_version`. Revocation is irreversible and serialized against intent; it bars future use, including a reserved old seal, but cannot undo a committed intent or refund an unknown hold. A seal pins `(scope, version)` at preparation. Dispatch acquires the pinned buffer before final intent checks and never calls `Getenv`, CredRead or “current key”. A version missing its in-memory bytes is unavailable, never rebound to a new secret. Sources: `docs/DESIGN-ROUTING-LAYER.md:254-266,890-913`; `.scratch/dwarf-harness/spec.md:163-169,413-419`; P3.

Open rebuilds version/revocation **metadata only**, reads no secret source and restores no send permit. After restart, owner binding creates a new version; old unsent attempts are recovery-only and may release, old sent attempts remain held/settle without a credential. This avoids pretending an environment variable/native target is immutable across process death without hashing or persisting authentication material. Sources: `docs/DESIGN-ROUTING-LAYER.md:254-266,890-898`; `internal/core/agents/doc.go:24-31`; P3.

Secrets live only in `internal/core/credentials`' Core-owned buffer and the one request header handed to `net/http`; never an Agent handle, prepared public value, launcher, execution guest, context object, canonical transcript, seal, quote, telemetry or error. Use no `String`/JSON/debug representation exposing them. On revoke/Close, overwrite owned byte buffers after active users drain and clear references; Go/net/http strings and OS memory are not a secure-erasure guarantee. Close cancels/drains active HTTP work, preserves all durable holds and wipes credentials; it never settles zero. Sources: `docs/DESIGN-CORE-AND-LAUNCHERS.md:158-162,1000-1008`; `internal/core/agents/doc.go:16-23`; `docs/ROADMAP-CORE.md:434`; P3/P9.

## §4 — Seal, input bound and exact quote
### 4.1 Immutable envelope and framing (P7)

Core prepares one immutable, deep-copied envelope containing provider; exact HTTPS authority (host and optional explicit port); exact escaped path; `POST`; explicitly selected model, region and requested tier; sorted semantic headers; pinned credential scope/version; valid UTF-8 **exact serialized body**; request hash; bound origin/turn/optional task; and pinned route/profile revision. The transport sends those exact bytes, never re-marshals or applies a default after pricing. Origin/turn/task, budget scopes and period are admission members, not extra members of the §5.3 request hash. Sources: `docs/DESIGN-ROUTING-LAYER.md:209-270`; `.scratch/dwarf-harness/spec.md:163-169,459`; ticket 13:30.

Use `net/url`, not a URL parser of our own. Refuse non-HTTPS, userinfo, fragment, query, opaque URL, empty authority/path, encoded/path ambiguity, unsupported authority or path, and headers outside the profile's closed semantic allowlist. Initial headers are exactly `content-type: application/json`, the pinned supported `anthropic-version`, and `accept: text/event-stream`; no beta, organization/project override or other semantic extension is accepted unless explicitly present and priced in a later supported profile. If enabled later, such headers must be sealed too, never injected after admission. Names are lowercase ASCII HTTP tokens, case-insensitive duplicates refuse, values reject CR/LF/control bytes and retain their exact permitted spelling. Host/Content-Length derive only from sealed authority/body. Authentication, Go transport framing and connection headers are not semantic hash inputs. Sources: `docs/DESIGN-ROUTING-LAYER.md:254-262`; `docs/DECISIONS.md:722-735`; P5/P7.

`frame(b)=u64be(len(b))||b`; text is UTF-8 bytes without Unicode normalization. Request SHA-256 preimage is the individually framed sequence **exactly**:

```
router-provider-request/v1, provider, HTTPS authority, model, region,
POST, escaped path, requested tier, credential scope ID, credential version;
u32be(headerCount);
for each byte-sorted header: frame(name), frame(value);
frame(exact body bytes).
```

Hashes are nonzero lowercase 64-hex SHA-256. No maps, float conversion, JSON “canonicalization” library, auth hash or ambiguous concatenation. `requestHash` covers the entire body, not its hash/parsed equivalent. Sources: `docs/DESIGN-ROUTING-LAYER.md:254-262`; P7.

Quote preimage is individually framed `router-cost-quote/v1`, **raw 32-byte request hash**, capability version, tariff version, lowercase-hex tariff hash text, `USD`, canonical-decimal maximum microdollars; then `u32be(componentCount)`. Each component encodes `u32be(classCount)`, byte-sorted distinct framed class strings, framed canonical decimals `maxUnits`, rate numerator, denominator; sort complete component encodings bytewise and frame each. Canonical decimal is `0|[1-9][0-9]*`; denominator positive. Refuse duplicate components, repeated/overlapping classes, invalid UTF-8, unsupported fields and arithmetic/length overflow. Sources: `docs/DESIGN-ROUTING-LAYER.md:260-262`; P7.

### 4.2 Independent rectangular maximum and settlement tariff

For the pinned endpoint `I_cap=min(inclusive_input_max,context_max)`, `0<O_req<=output_max`. Never subtract requested output from input. Choose the largest exact applicable rate among **input classes the sealed request may incur**, including cache writes and every permitted served-tier/region/threshold rate; independently choose the largest output rate. Two quote components cover all eligible input classes at `I_cap` and inclusive generated-output at `O_req`. Tool/schema/system tokens are already inside inclusive input, once. Reasoning is a subset of generated output, not another output maximum. Cache optimism/token-count estimates cannot lower the hold. Sources: `docs/DESIGN-ROUTING-LAYER.md:743-761`; ticket 13:31.

Rates are exact nonnegative rational **USD per million tokens**, numerator/denominator each canonical decimal ≤MaxInt64, denominator >0. Use bounded `math/big.Int` / `big.Rat` scratch arithmetic; validate numeric lexical bounds before allocation. Compute

```
maximumMicros = ceil(I_cap * maxInputRate + O_req * maxOutputRate)
```

by adding exact rationals and performing **one final upward division**, because the million-token and microdollar factors cancel. Components carry no separately rounded amount. Refuse admission when maxima, components or final maximum exceed supported int64 or cannot be proved finite; never saturate. The full per-class tariff (not only the maximum rates) is pinned for later settlement; tariff SHA-256 covers its exact validated profile encoding. Sources: `docs/DESIGN-ROUTING-LAYER.md:745-761,908-914`; P5/P7.

Required named vectors: `input_plus_requested_output_above_context` uses the source's documented overflow-accepting profile and proves full input reservation; `input_rate_above_output_rate` uses a synthetic supported local tariff (e.g. input 9, output 1) so an accidental min/tradeoff under-reserves; `one_final_rounding` uses fractions whose separately rounded sum differs; `input_class_overlap`, `cache_aggregate_not_added_to_ttl_children`, `reasoning_not_added_to_output`, `quote_overflow` and `post_quote_change_before_intent` fail respectively on overlap, inclusive double count, overflow or changed endpoint/header/body/model/tier/credential. Synthetic tariff evidence is local arithmetic, not provider pricing. Sources: ticket 13:30-31; `.scratch/dwarf-harness/spec.md:611-613`; `docs/DESIGN-ROUTING-LAYER.md:743-761`; P7/P14.

## §8 — Settlement, correction and recovery
### 8.1 Settling evidence, never guessed outcomes (P11–P12)

Financial certainty and model success are separate. A known final `max_tokens`/tool-use/other supported stop with complete usage settles; a successful HTTP status or clean EOF without that usage does not. Normalize exclusive classes, price their exact reported units at the **admission** tariff/served-tier mapping with one final upward rounding, and replace the attempt's one hold with that cost in its original admission period. Scope membership never follows current route, credential rotation, task reassignment or view focus. Late usage works after period rollover or revocation and needs no current spend permission, because it accounts for already-intended work. Sources: `docs/DESIGN-ROUTING-LAYER.md:743-761,875-914`; ticket 13:37; P11.

Duplicate evidence is identified by `(AttemptID, evidence SHA-256)` over the exact bounded context-owned observation artifact. Same evidence/new command ID returns the already recorded result without charge/release; same command/different canonical submission refuses `ErrCommandMismatch`. A different complete final observation cannot silently overwrite one already settled: host-only `CorrectPaidSettlement` must explicitly name the previous result sequence/version/evidence digest and supply replacement complete evidence for the **same provider request/message**. A correction records the replacement units/amount, adjusts original-period settled total by the delta once, releases no hold twice, and preserves all prior evidence; stale/conflicting correction refuses. No owner-entered dollar refund, inferred tax/invoice allocation, zeroing unknown or reconciliation network client. Sources: `docs/DESIGN-ROUTING-LAYER.md:890-914`; `docs/DECISIONS.md:722-727`; ticket 13:37; P12.

Only §7.3's documented final pre-output refusal rule permits no-charge settlement without fully priced usage. Generic HTTP error, client cancellation/timeout/disconnect, empty text, token-count0, a request ID or the support article's unspecific “failed requests” sentence does not. `released_unsent` is not provider zero settlement. Preserve category/output-started/final-completion evidence and rule ID in the result so replay can check it, never infer no-charge from an absent usage field. Sources: AF:326-341; `docs/DESIGN-ROUTING-LAYER.md:875-898`; ticket13:35-37; P11.
State machine: reserved(v1)→intent/SENT(v2) or released_unsent(v2); SENT→unknown or usage/no_charge; unknown→new bound unknown evidence or final usage/no_charge; settled→only duplicate or explicit correction. Every effect after reserve uses exact current expected/new=expected+1. Unknown ends the work child once but retains money; later evidence does not create another child ending. Financial settlement/correction after revoke, parent end or context focus change uses original scopes/period. Result output_started is OR(previous recorded witness,current observation); never erase it through unknown/correction. Reconcile is explicit for recovered/inactive dispatch; active same-incarnation HTTP returns busy until cancelled/drained. Sources: routing:890-914; ticket11 ruling:27; ticket13:35-37; P8/P11/P12.

### 8.2 Crash/recovery matrix

`Open` streams complete committed groups through the same paid reducer as preflight. It reconstructs static route/profile history, credential-version/revocation metadata, spend terms, periods, attempt states, holds/settlements/corrections/violation fences and receipts; validates historical authority at its original ledger position; verifies selected private objects; **reads no clock/source/credential, appends no record and sends no request**. Missing/corrupt private artifacts are reported/blocked, not substituted, while the ledger alone still determines all financial exposure. A missing result artifact cannot release a hold or erase a settled amount. Sources: `docs/DECISIONS.md:670-675,706-711`; `docs/DESIGN-ROUTING-LAYER.md:890-914`; `internal/core/agents/doc.go:24-31`; P11/P13.

| Interruption window | Recovered state / only permitted next accounting action |
|---|---|
| Before request-object publication/reservation Submit, or torn reservation group | No admitted attempt/ID/hold. Orphan private object confers no permission; explicit new admission may reuse an unconsumed command. |
| Reserved durable, projection/ack lost; or after reservation but before intent | One reserved full hold. No send permit survives; report recovery pending, explicit reconcile releases it `released_unsent`. A duplicate admission returns its receipt, never sends. |
| Torn/uncommitted intent | Store truncates it; still reserved and provably unsent because no network byte was permitted before confirmed durability. Explicit release only. |
| Intent durable, before send token/network bytes; uncertain intent write | If committed: SENT/unknown, full hold even if no bytes left. If store write uncertain: poison incarnation, send zero in that invocation, recover exact ledger outcome; never guess/reuse a token. |
| POST partial/full send, stream partial/final usage only in memory | SENT pending/unknown, full hold. No retry. Complete late bound evidence may settle explicitly; EOF does not. |
| Final artifacts published but result not committed / torn result | SENT unknown/held; unselected artifacts are not settlement. Trusted late observation can explicitly settle once. |
| Result/correction committed, projection/ack lost | One latest settlement/correction at original period, one hold release, retained true violation state. Receipt/evidence retry changes nothing. |
| Overrun acknowledgement committed, ack lost | Exact acknowledged fence cleared once; costs/unknown holds unchanged; offending route remains disabled until an authorized new revision. |
| Revoke, cap change or rollover concurrent with a transition | Ledger order wins; no copied allowance, released uncertainty or grandfathered pre-intent authority. |

`Reconciliation.PendingPaid` lists attempt ID/version/origin/turn/state and held maximum; recovery/host methods resolve one exact attempt with original identity. `unknown` records the ending matching its start and keeps money; later complete evidence may settle it. Source: `contract/ledger/doc.go:1910-1928`; `.scratch/dwarf-harness/c3-evidence/ticket-11-design-ruling.md:27`; ticket 13:35-37; P11.
