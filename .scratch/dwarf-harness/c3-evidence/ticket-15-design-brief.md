## 2. Turn lifecycle and single continuation owner

### 2.1 Runtime states and precedence (P2/P3)

`admitted → ready → model_running → ready_tools → tool_running → ready` repeats within the immutable binding. `waiting_required` holds an unresolved required effect/result, `yielded` is a ready turn put at the back of the rings, `stopping` admits no new effect while already-started work drains, and `finished` is terminal. These are process-local scheduler projections, not new workflow/task states. `ready_tools` carries the ordered outstanding provider call IDs; a model's natural stop is a *request to finish*, not authority to override them. Tool handlers return typed facts, never a `continue` boolean or another model call. Sources: ticket 15 `:35`; D88 item 5; `internal/core/agents/doc.go:197-210,477-485`.

At **every scheduling selection and immediately before any model/tool effect**, apply this order:

1. Cancellation requested, host shutdown, lost current authority/assignment or integrity fence: enter stopping, cancel cancellable I/O, dispatch nothing else.
2. Else deadline reached or the applicable next-dispatch counter exhausted: stopping with `deadline` or `loop_limit`; no “one last” finish/model/tool call.
3. Else unresolved required results: wait. If the next required tool is not yet dispatched and limits permit, schedule that tool, not a model call. A finish request cannot bypass it.
4. Else a completed natural answer can finish; otherwise mark ready at the tail, and obtain **fresh** concrete authority and resource admission when selected again.

Stopping is not proof that an intended effect was prevented. Record observed local/paid endings through existing host entrances; unsent reservations may release, uncertain sent work ends unknown and remains held. Only after children have endings and writers are observed/closed may `EndTurn` release/cancel/interruption close the slot. Unknown is an ending, not success. No callback directly revives or starts a turn. Passive non-required request results remain for that context's next natural turn/status; no completion-only call. Persistence and restart/race proof of waits remain ticket 16. Sources: ticket 15 `:35`; `contract/ledger/doc.go:1948-1958`; `internal/core/agents/doc.go:197-210,477-485,566-570,620-624`; D53, D63.

### 2.2 F3-15 exact additive family (P1)

Owned codec files: `contract/ledger/loop.go`, `loop_submission.go` and tests/fixture directory `testdata/f3/15/`; package documentation and catalogue/register are updated in S2. Add version 1 types:

| Type | Ordered payload members |
|---|---|
| `private.turn_revision` | `scope:"context", expected_version, revision, changes` — reuse PrivateRevision/PrivateChange semantics, but permit exactly one transcript append; expectation ≥1, revision=expectation+1 |
| `runtime.turn_bound` | `turn_id, admission_sequence, input_object, policy_object, render_object` — three owning-context ObjectRefs; `admission_sequence` identifies the exact existing F3-11 admitted turn |
| `runtime.tool_started` | `tool_id, parent_turn_id, attempt_id, provider_call_id, tool_name, tool_schema, request_object, request_sha256, operation, target?, effect_command_id?` — effect_command_id required only when a native mutating/accounted entrance will be called |
| `runtime.tool_result` | `tool_id, started_sequence, outcome, result_object, effect_receipt_sequence?` |
| `runtime.turn_result` | `turn_id, bound_sequence, outcome, reason, model_calls, tool_dispatches, final_message_object?, ending_sequence` |
| `runtime.loop_receipt` | `command_id, submission_sha256, submission, outcome, effect_sequence` |

ObjectRef is F3-11's exact `{sha256,bytes}`. New payload/submission/whole-receipt cap is 65,536 bytes, matching F3-11/12/13/139; it bounds the complete input before parsing and compact output separately. F0 recursive duplicate rejection, plain unsigned integers ≤MaxInt64, canonical UUIDv7/digests, unknown optional-member handling and no-null-known-member rules apply. `tool_schema` is positive; this producer writes 1. Names are stable ASCII tool identifiers, provider-call IDs bounded visible ASCII (≤256 bytes, matching existing artifact support). Outcome/reason/operation are open tokens using the existing 64-byte token grammar; current writer values are specified below, and unfamiliar values are held/unsupported, never assumed successful. `target` reuses the existing Resource; omit it for syntax errors/catalogue queries, never encode an inaccessible target. No raw args/text, credential locator/value, secret-derived identity or body_refs enters the family. Sources for reused rules: `contract/ledger/doc.go:1593-1605,1630-1667,1764-1827,1939-2009`; `internal/core/agents/doc.go:704-746`. New names/shape/cap are P1.

F3-15 bind/tool-start/tool-result groups are exactly `[ledger.command, matching runtime effect, runtime.loop_receipt]`; loop.end is exactly `[ledger.command, private.turn_revision, runtime.turn_result, runtime.loop_receipt]`, one Submit each. Publish each private input/request/result object before the record selecting it. The append-only runtime/paid journal is the canonical source during an active turn; publish **one bounded turn-manifest transcript append at loop.end**, not a private-head revision for each model/tool journal event. Otherwise the runtime's own journaling would make every model-observed context-memory CAS stale. This keeps existing whole-scope revision semantics: ordinary read→CAS works if no actual private write intervened, and a concurrent owner/private change still refuses. All record identities bind the same agent/session/context/turn, operation_id=command_id; effect/private actors core, command/receipt owner for owner input, agent for model invocation, core for observed result/finalization. Receipt/effect sequences are actual readback identities, never predictions. The same reducer validates original normalized input, full groups and prior state live and at Open; uncertainty poisons. Sources: `contract/ledger/doc.go:1630-1667,1686-1735,1986-2025`; `internal/core/agents/doc.go:48-90`; D33, D37, D50; P1.

**Schema-6 submission:** compact JSON in order `schema:6, actor, origin, turn_id, operation, expected_version, arguments`; `origin` is existing `{agent_id,session_id,context_id}`. `expected_version` is 0 for loop.bind/tool.begin, 1 for tool.result/loop.end (one immutable matching terminal per started/bound record); it is not the independent private revision expectation. Operation argument order: `loop.bind` is `turn_id,admission_command_id,input_object,policy_object,render_object`; `tool.begin` is the exact tool_started order in the table; `tool.result` is the exact tool_result order; `loop.end` is `turn_id,bound_sequence,outcome,reason,model_calls,tool_dispatches,final_message_object?,ending_command_id`. Validate actual admission/ending/started/effect receipts at their supplied source identities and derive their sequence fields from readback. Canonical manifests/revision predecessors derive from current private state, never caller guesses. Hash the full normalized argument object (tool path, schema version and concrete target included) through request_object/request_sha256. Before minting an internal effect/admission/ending command ID, perform the global authorized outer-command lookup; reuse its recorded internal IDs, original policy/deadline and render selections when comparing a retry, never generate a new meaning or a new deadline. For a new tool command, retain the normalized bytes and fixed effect ID through completion. Same command/principal/digest returns its receipt after current disclosure authorization; mismatch refuses globally across all six submission families. IDs are Core-minted UUIDv7, never derived from provider strings or used as permission. No F3-11/13 command reuses the outer ID. Sources: `contract/ledger/doc.go:2028-2077`; `internal/core/agents/doc.go:77-90,214-229`; D37. This form is P1/P6.

`loop.bind` first obtains the ordinary Agent.StartTurn receipt with its separate admission command ID, then publishes input/render/policy and the bind group **before** the first dispatch. Serialize these steps for that context, but never call StartTurn recursively under Service.mu. A busy admission commits no loop binding, retains no start and queues no work. A crash/failure between admission and binding is an orphan existing admission, recovery_pending and nondispatchable; it is never silently converted to queued input. A same-ID outer retry first compares the complete bind digest; an orphan's fixed admission/turn IDs are queried, not replaced, and it refuses recovery_pending if completion cannot be proven. On a definite pre-bind publication failure, close the never-dispatched admitted turn honestly; on uncertainty poison and recover. This intentionally preserves both frozen commit shapes rather than inventing atomicity across two commits. Sources: `internal/core/agents/doc.go:186-210`; `contract/ledger/doc.go:1986-2009`; ticket 15 `:30,34`; P1.

Tool-start is a durable “Core accepted this invocation”, **not** effect authorization or proof of execution. File operations still have F3-11 admission/dispatch/end; atomic Core operations still use their native command/effect/receipt group; catalogue/status operations freshly authorize and have the F3-15 start/result pair. An already-started invocation is never executed again merely because no result is recorded. Unknown unpaired work is recovery_pending, not success; ticket 16 adds the crash reconciliation proof. Each provider call already has its F3-13 reserve/intent/result, so no duplicate paid ledger or new money record is added. Sources: ticket 15 `:32,35`; `docs/CONTRACTS.md:121-151`; D37, D88.

`runtime.tool_started` is also a required-result child of its parent turn; its one matching runtime.tool_result is its ending and releases **no** local/money accounting. The existing EndTurn/CancelTurn child-free predicate must consume this F3-15 relationship as well as F3-11/F3-13 children, so even a native local ending cannot let another trusted entrance skip the still-unrecorded tool result. New family consumers of turn-child completion must consume all three families; record this additive reading explicitly at freeze, as F3-13 did. An unknown_effect tool result ends the journal child but causes the live loop to stop/wait safely, not report a successful required effect; original unresolved holds remain. Sources: `docs/CONTRACTS.md:140`; `contract/ledger/doc.go:1948-1958`; `internal/core/agents/scoped_work.go:155-169`; D148; P1/P2.

For a rejected malformed invocation, tool_started uses operation `invalid_argument`, no target/effect_command_id, and a private request object `{schema:1,tool_name,raw_arguments_sha256}` after the literal-secret check; raw rejected evidence, if retained, is a bounded private JSON **string**, never executable RawMessage. Its paired result uses outcome `invalid_argument` and the static correction. Unknown/invalid tool names are represented as `unrecognized`, never echoed. Other tool-result writer outcomes are `ok`, `denied`, `busy`, `conflict`, `too_large`, `unavailable`, `unknown_effect`; they describe observed facts, not continuation decisions. A same `(attempt_id,provider_call_id)` can select only one tool ID and request digest. A second terminal/result or changed call meaning refuses. Model-supplied call IDs cannot alias another attempt/context's command. Sources: ticket 15 `:32-35`; `internal/core/agents/doc.go:704-746`; P1/P6.

`loop.end` follows the existing host EndTurn receipt. `runtime.turn_result` outcomes are `finished`, `cancelled`, `failed`, `interrupted`; reasons include `natural_stop`, `cancelled`, `shutdown`, `authority_lost`, `deadline`, `loop_limit`, `provider_error`, `content_invalid`, `unresolved_result`, `integrity` and `scratch_pending`. `finished` requires a complete validated natural answer, a selected final-message object (possibly with an empty text-object list), and no required pending result; it never means task completion or promotion. Cancelled/failed/interrupted omit final_message_object. F3-11 ending is `released` for normal/failed loop closure, `cancelled` for cancellation, `interrupted` for shutdown/interruption. Do not reinterpret `released` as model success. Sources: `internal/core/agents/doc.go:197-210`; ticket-11 ruling `:22-23`; D33, D37.

**Shared-head compatibility:** private.turn_revision joins private.revision/private.scoped_revision on the *same* context revision/transcript predecessor. All private-head readers/queries, source-reference validation, integrity/history traversal, current live installation and historical reconstruction must consume it; an old-family-only private-head consumer is not valid on such a log. F3-15 does not change old bytes, group rules, schemas, goldens, task state, work/book semantics or paid interpretations. Open reduces metadata but never sends, reads credential sources or paid objects, resumes waits, or auto-executes tools; it reports unmatched loop/tool records as recovery_pending. ## 3. Fair bounded scheduler

### 3.1 State placement and rotation (P2)

Keep one concrete `loopRuntime` field on `agents.Service`, and metadata-only F3-15 replay projection beside existing `projection.work`. One active entry per admitted turn contains immutable origin/turn/task, selected static route/credential version, policy, transcript head, state, pending tool/result IDs, counters, cancellation context, writer handles and bounded live-text state. Ready rings contain only existing admitted work: one agent marker and one context marker, de-duplicated. Dormant contexts have no worker, timer or channel. Historical completed turns live in the ledger; current metadata uses the existing bounded history cache rather than an immortal per-turn map. Sources: `internal/core/agents/service.go:71-140`; `internal/core/agents/doc.go:346-384`; `docs/DESIGN-CORE-AND-LAUNCHERS.md:918`; D22, D50, D88.

Round-robin ready agents, then that agent's ready contexts; each selection receives one model-call or one tool-call quantum, then goes to its respective tail if ready again. Tool calls from one response execute in provider order, serially within the turn; each yields to other ready contexts. I/O runs outside Service.mu and the scheduling lock. In-flight workers are bounded by admitted turn slots, with the existing MaxActivePaid/physical book limiting model exchanges; never spawn a worker for a refused start. A busy paid/local admission leaves the already-admitted turn visible as `waiting_resource`; retry it only on a resource-release/configuration-change notification, not a loop, sleep or model call. One host timer tracks the earliest active deadline; ready/result/cancel/authority/resource transitions wake the scheduler. Waits occupy the turn slot until honest ending. Sources: `docs/ROADMAP-CORE.md:437,445,492`; `internal/core/agents/doc.go:175-210,573-593`; ticket 15 `:30,35`; P2.

The Service owns the single appender and BudgetBook already; no scheduler wallet, task database, persisted ready queue or R1 cache planner. Configuration changes/revocation wake the scheduler, but final authorization remains the existing current chain, not the wakeup reason. Ticket 90 will insert eligibility into this same selection/dispatch function; no allow-all eligibility stub is installed now. Sources: D50, B7, B9, D88; `docs/ROADMAP-CORE.md:445`; ticket 90 `:27-32`.

### 3.2 Immutable finite policy and limits (P3)

`TurnPolicy{Schema:1, MaxModelCalls, MaxToolCalls, DeadlineUTCNS, MaxArgumentBytes, MaxResultBytes, MaxDiscoveryEntries, MaxSearchEntries, MaxSearchMatches, MaxLiveBytes}` is set by the trusted host and selected in policy_object. No field is model-controlled or mutable mid-turn. Positive checked integers, deadline strictly after host admission time; all byte/count values must fit enclosing inherited payload/object/request/buffer support. Sample the existing guarded host clock at admission/dispatch, with a monotonic timer in-process; regressed/unavailable time refuses further dispatch rather than extending a deadline. No timer is authority to resume after restart. Sources: ticket 15 `:33-35`; `internal/core/agents/doc.go:274-312,754-780`; P3.

Testing terminal defaults: **16 model calls, 64 tool calls, 10-minute turn deadline, 64 KiB raw args, 64 KiB encoded result, 8 catalogue entries/page, 4,096 search entries examined, 100 search matches, 8 MiB cumulative live text/turn**. These are finite runnable settings, not owner money/capability ceilings or measured fit. Terminal `max_output_tokens` remains explicitly selected for the configured profile (no invented model/output default); fixture requests use 4,096 output tokens. Tests set smaller counters to exercise exhaustion. Each accepted provider tool invocation, including an invalid-argument correction and catalogue/status request, consumes one tool counter; increment before its local handling so endless malformed calls cannot evade the cap. Each newly reserved paid attempt consumes one model counter; a receipt replay consumes none; a proven-unsent refusal does not automatically retry. Counter exhaustion prevents the *next* dispatch, not recording or draining existing work. The full model/turn money maximum is at most the checked sum of per-attempt sealed maxima, never an advance permission to spend it. Sources: ticket 15 `:30,34-36`; D79, B9, D88; `internal/core/agents/doc.go:510-555,573-624`; P3.

For counters, “exhausted” means the next candidate model/tool dispatch would exceed its respective maximum; a natural final answer returned by the last allowed model call may finish without an extra dispatch if its deadline is still valid and all required results are resolved. A response requesting more tools than remain cannot bypass the limit: stop before the excess effect and do not send a partial batch to the provider. Deadline/cancel/authority precedence still wins over a newly requested finish. Sources: ticket 15 `:35`; P2/P3.

Reserve retained render/live/result/correction bytes through the existing physical preparation book before copying or admitting the runtime binding; do not confuse these with consumed units or money. Reuse the request compiler's 512 KiB paid-body cap, 1 MiB private-object support and paid exchange reservations; extend `requestStorageBound` to count every newly replayable artifact byte and escaping allowance. A request/result that cannot fit refuses or returns explicit bounded `too_large`; never silently truncate canonical args, artifact signatures, a required result or final message. Search snippets/pages may be explicitly incomplete as their result schema says. Sources: `internal/core/agents/paid_prepare.go:15-59`; `internal/core/agents/doc.go:54-62,754-780`; P3.

## 4. Core command/event interface and terminal

### 4.1 Core interface and attribution (P4)

Add `Service.EnableTurnLoop(ctx, workspaceService, LoopOptions) error` (one invocation per Service incarnation; repeated identical configuration is no effect, conflicting enable refuses), and `Service.OpenSession(ctx, Binding) (session.Session,error)` as a **trusted-host owner-view** entrance for one registered agent and its existing sole execution session. Enable starts the concrete scheduler only after replay/current-service checks; plain Open/OpenPaid alone still starts nothing.
