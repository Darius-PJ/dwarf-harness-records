# Ticket 04 design ruling (advisor AdvisorT04, 2026-10-12)

Ruling on [the ticket 04 design brief](ticket-04-design-brief.md). Where the two differ, this ruling wins. The owner's approval of the design (OG-A) and his answer on the validation policy's parameter set (OG-B) come before any code.

**Verdict:** approve-with-changes.

The design is correct against §13.4, D47, B12, D45 and the ticket's five criteria. P1 is what the sources require, not a second policy source. All findings are minor or nits: pin the CRLF vector's digest, state in doc.go that phase-1 rules are format-family invariants and that within-phase error order is not a compatibility promise, follow AGENTS.md for the B-entry's originator, add one uint64-overflow rejection row. OG-A and OG-B are genuinely the owner's; nothing else in the brief is.

## Notes for the coder

1. Order of phase 1 exactly: len(data) > Bytes first (so FF padding gives bytes, not invalid_utf8); then BOM prefix EF BB BF; then utf8.Valid over the whole input (encoding/json silently substitutes U+FFFD, R1); then the token walk. Never use json.Valid as a pre-check: it accepts duplicate keys and double-scans.
2. Call dec.UseNumber(); check each json.Number's text with a parseNat-style digit loop against the member's max (overflow-safe, never via float64). Leading zeros (00, 007) are decoder syntax errors (R1) → Malformed{syntax}, so do not pre-empt them as not_unsigned_integer (M18).
3. Trailing data: after the root value, one more dec.Token() must return io.EOF; any other result, including a SyntaxError on 'x' or a NUL byte, is Malformed{trailing_data} (M12/M13), as ledger/envelope.go's checkPayload does. Alternatively scan data[dec.InputOffset():] for non-JSON-whitespace.
4. Keys vs values come back from Decoder.Token as plain strings; track per-container state (the house level{keys, expectKey} stack). Compare decoded keys, so "law\u005fid" duplicates law_id (M10). Members counts the duplicate too and is checked before duplicate_key.
5. Depth: root container = 1; a container opened at depth > Depth fails at its opening token. Tokens: count every value Token returns including keys and Delims; commas/colons do not exist as tokens. StringBytes: len() of the decoded Go string, keys included.
6. Phase 2 checks only format, schema_version, evaluator_version, kernel (policy: format, schema_version), in that order, each as absent→missing_field, wrong type→wrong_type, other value→*UnsupportedError with the decoded string or the digits as written (N2's 20-digit value stays verbatim). Unknown root members are NOT reported before this (schema-version-2.json).
7. Phase 3 per object: unknown members first (first in input order), then missing in table order, then each member's type then value rule, then cross-member rules (saturation > cutoff at /…/saturation_units; numerator < denominator at /…/numerator; edge_types == profile list at /…/coupling/edge_types). Per array: count, then every element, then ordering (so a 7th kind is `count`, a swap is reported at the later element's id/rule_id path, equal neighbours are `duplicate`). This ordering is what I13–I15, I22, I47–I52 expect.
8. Kind completeness needs no separate check: count == 6 + strictly ascending ASCII + closed six-value enum implies all six present; put that reasoning in a comment. Source unit must equal the enclosing kind's unit (U:450 'use the declared kind unit'); kind unit mismatch is reported at /kinds/i/unit before any source is read.
9. Registry: keep rules as a slice ordered by rule_id (deterministic); maps are fine for lookup but no reported error may depend on map iteration. Each error wraps exactly one sentinel via Unwrap; never return a raw strconv/json error (FuzzLoad's single-sentinel property).
10. Empty/whitespace-only input (M5) must reach the walker and come back as Malformed{syntax}, not panic: guard the BOM check with a length test; utf8.Valid(nil) is true.
11. Escapes: \u0061ffordance decodes to affordance and is valid with a different digest; an escaped lone surrogate decodes to U+FFFD and falls to pattern/unknown_value/unknown_field. Document both in doc.go (finding 6). Raw control bytes inside strings are decoder syntax errors.
12. Expected golden values (expectedFull/expectedMinimal/expectedBounds/expectedPolicy) are hand-written literals or a test-local table transcribed from §13.4 — never the package's unexported registry and never loader output. Internal test package is the house convention; either way use only exported API.
13. Mutation helper: anchors must occur exactly once in full.json. Kind-level `"unit": "affordance_units"` also appears in each of that kind's sources, so include indentation or the preceding member in the anchor; the uniqueness assertion will catch misses. Copy the golden bytes per subtest before t.Parallel().
14. Goldens: generating full.json with a throwaway script (not committed) then checking it by hand against §3 is fine; the committed bytes are what matter. Formatting rule: json.Indent(compact, "", "  ") + one LF; full-compact.json has NO trailing newline (editors add one; V6 i/none and TestIdentity's json.Compact equality catch it); full-reordered.json reverses member order in every object including coupling, arrays untouched. No BOM. Compute every pinned digest with Get-FileHash and lowercase it; also pin the CRLF-derived digest (finding 3).
15. Token-limit generator: compact 2048 = 5 + 15·(2+127) + (2+106); standard 8192 = 5 + 31·(2+255) + (2+218), outer array 32 elements, all within the other bounds. Members generator keys k0000… give a root object that fails later with missing_field /format, which the test tolerates (any non-LimitError).
16. Offsets in LimitError/MalformedError are cheap values (dec.InputOffset(), SyntaxError.Offset, index of the first invalid byte, 0 for bom); tests should not pin them beyond bom=0.
17. LoadLimits validation (phase 0) runs before touching data; CompactV1()/StandardV1() return fresh values; no package-level mutable state, no init(), no goroutines, no file/clock/env reads. Both loaders share phases 0–2; the policy head has two members and a 1..uint64 domain with the cross-member rule.
18. OG-B gates only S1b: the policy golden, expectedPolicy, VP15/VP16 and ExampleLoadValidationPolicy's pinned output (which embeds the policy digest) change with the answer. S1a (field law) can start on OG-A.
19. Fuzz seeds: f.Add every golden and every reject-table input; keep testdata/fuzz only for crashers found and fixed. Run V2 for 120 s per target as for tickets 02/03.
20. S2: the B-entry's originator follows the owner's OG-A words (adopted/modified), OG-A and OG-B answers quoted verbatim on their own lines; RU:577 stays true ('must still be frozen') and needs no edit; U1 status changes in RU:217 and R:187 in one commit.
